## 4. 不能随手改的设计决策

这五条是文档的骨架，改动前先读对应章节的论证。

1. **三态与非对称默认**（7.3 / 7.4）：无信号不计入判定；压缩到 C 需要两个以上一致正信号，降级到 A 只需一个负信号，其余维持 B。撤桥的错误成本高于铺桥。
2. **地板条款**（7.4）：层级 A 的微过程仍失败时，允许退回完全显性教学。这是全文对"不先给定义"的唯一豁免，且必须保留"正信号即回升 A"的路径。
3. **C 层检查点**（7.4）：压缩层必须保留一个无标注的边界微变体，负信号触发 C→B 回退，且不告知用户。
4. **清单只增不减**（5.1）：删除检查项需要在 PR 里写明理由；否则清单会在迭代中失守。
5. **平台无关与诚实声明**（第 0 章 / README）：不得引入对特定模型、IDE、插件的依赖；引用只背书概念来源，不得写成有效性证据。

## 6. 已知坑

- **本机 g++ 链接器故障**：MSYS2 的 `ld` 返回码 5，连 hello world 都链不上；`g++ -c` 正常。做算法验证时不要在这上面耗时间，改用 Python 等价实现 + 暴力对拍。
- **示例课与 fixture 是两份文本**：`examples/*.md` 含标题和标注，`check_lesson.py` 的校验对象是 `tests/fixtures/*.txt` 里的纯课文五段。改课文时两处都要改，否则测试通过但文档过期。
- **SKILL.md 由母本文档装配而来**：装配脚本没有入库，母本已冻结，之后直接编辑仓库副本，不要再走"改母本再装配"的老路。
- **版本号三处同步**：frontmatter、CHANGELOG、tag，漏一处会让安装端显示旧版本。
- **Windows 路径**：仓库内文档一律用相对路径，不要写入 `C:\Users\...` 之外的机器相关路径。
