# 设计说明

这份文档解释 Skill 为什么长成这样，以及它明确不解决什么。正文以 `skills/algo-implicit-heuristics/SKILL.md` 为准，这里只记取舍。

## 核心判断

算法题之间的差别在知识点，可迁移的部分在**认知状态**：看到某类结构时，脑子里先浮现的那个"这到底在做什么"。把 Skill 写成"知识点 → 模板"的映射，会膨胀成题解目录，遇到新题仍然失效。

所以这份 Skill 不存答案，存**制造判断的条件**：

- 两个几乎相同、只差一个参数的案例并置，差异由读者自己发现；
- 参数微调让边界以案例形式出现，而不是以警告形式出现；
- 一个更根本的动词反复出现，概念名在读者走完过程之后才落地。

## 为什么需要诊断层

隐性启发有一个前提：读者具备最低限度的前置概念。缺了它，并置案例无法触发迁移，因为读者没有用来比较的框架。

诊断层不靠提问，靠行为：对"哪个变了"的定位、复述的粒度、在微变体上的独立推进。每个信号按正/负/无三态记录，无信号不计入判定。层级调整的门槛不对称——压缩到 C 需要两个以上一致正信号，降级到 A 只需要一个负信号，其余一律维持 B。理由写在 SKILL.md 7.4：撤桥的错误成本高于铺桥。

## 三个不容易察觉的设计决定

**1. 允许显性教学，但只在地板层。**
如果层级 A 的微过程仍然失败，说明知识缺口低于隐性启发能触发的门槛。此时坚持"案例先行"是空转，允许退回完全显性的定义与示范。这是全文对"不先给定义"的唯一豁免，且有进入条件和回升路径。

**2. 压缩之后保留一个检查点。**
C 层撤掉了脚手架，误判的失败是静默的。所以 C 层必须留一个融入正文的边界型微变体，负信号触发 C→B 回退，回退不告知用户。

**3. 验收清单是下限。**
清单能查句式、位置、数量，查不出"这段讲解有没有真的让人产生疑问"。通过清单不保证有效，未通过一定违规。这个区别写进了 5.1，避免把工具当成质量证明。

## 已知局限

- **可触发性是概率性的**。并置案例可能被略过，微变体可能被跳过。设计上接受"允许错过"，代价是覆盖率。
- **信号是弱信号**。复述粒度受表达习惯影响，单次信号不做刚性判断；跨两个以上采集点的一致才用于调整。
- **成文模式诊断能力有限**。一次性产出文本时，信号一、二没有采集点，只能靠冷启动加探针前置，判定延后到用户首次回应。
- **模块覆盖窄**。目前只有 A、B 两个实例；新题依赖 3.2 的现场声明路径，声明质量取决于执行者。
- **未做实证**。三处引用只背书概念来源，不构成有效性证据。

## 与苏格拉底式教学的关系

不替代，补位。苏格拉底式提问假设用户准备好停下来思考；阅读场景里用户往往在看题解，显性提问会被跳过或引发防御。这份 Skill 把冲突、脚手架从"对话中的干预"搬到"文本中的结构"。区别在于载体，不在于目标。
