# Python 学习目录规则

本规则用于本目录及子目录中的教学、出题、作业检查和路线图维护。

## 出题与阶段推进

- 工作前阅读 `教学路线图.md`，按已学内容、现有作业和阶段训练状态安排后续。
- 每部分必须包含基础训练、至少一道综合题和至少一道有难度的挑战题。
- 综合题至少组合三个已学知识点；后续继续安排跨部分综合题，复习旧知识。
- 挑战题通过问题拆解、边界分析、规律或调试提高难度，不依赖尚未讲解的语法。
- 挑战题以目标和约束为主，减少逐步解法提示，避免只重复上一题流程；根据实际表现复评难度，偏易时追加独立拆解训练。
- 使用仓库多本电子书的练习作为参考；核实相关章节后注明来源，区分原题、改编题和自编题。
- 具体题意、必要知识说明、样例和检查重点写入新的编号 `.py` 文件，保留作答区。
- 题目按“难度/知识点分类/题目文件”存放：第一层为 `基础题/`、`综合题/`、`挑战题/`，第二层为 `输出与变量/`、`字符串处理/`、`数字与运算/` 等知识点目录。
- 同一知识点在不同难度下使用相同目录名，按需增加目录；题号跨分类连续递增，保留已有文件名。
- 综合题按主要训练主题归类；没有单一主题时归入对应难度的 `跨知识点综合/`，在路线图相关部分登记链接。
- `教学路线图.md` 和本规则保留在学习目录根部；新建或移动题目时同步所有相关链接，使用相对于路线图的路径。
- 不覆盖学生已有答案，未被要求时不直接给完整解答。
- 新题创建后、回复前，必须同步在路线图对应部分加入有效的相对文件链接。
- 链接旁标明题号、题型（基础/综合/挑战）、检查状态；阶段题创建后替换对应的“待出题”。
- 路线图保留细化知识点和训练覆盖范围，不放具体题意、答案或长篇讲解。
- 知识点覆盖、综合题与挑战题检查完成后才将整个部分标为完成。
- 用户要求跳转时遵从安排，并记录未完成的阶段训练，后续适时补充。

## 作业检查

- 读取学生已保存的文件，检查实现方式，并在可运行时实际执行核对。
- 综合题、挑战题按题意检查有代表性的正常与边界情况；需要时在内存中变更测试数据，不改学生答案。
- 分开反馈核心知识、结果正确性、边界问题、输出格式与代码风格。
- 普通练习中的非关键格式差异不阻止核心知识过关；严格判题格式在出题时明确。
- 先给具体、分层提示；用户要求完整答案时再给解答。
- 检查后同步路线图状态：完全通过、核心已掌握（注明差异）、待修改或待检查。
- 不将“核心已掌握”写成严格输出和全部要求都已通过，不把基础题完成当成整个阶段完成。

## 当前约定

- 学生主要在编辑器中写题，保存后用“检查作业”等短指令触发读取与检查。
- 交流使用中文，以掌握知识和逐步独立解决问题为目标。

## 标准输入评测（第10题起）

- 新题使用真实 `input()`，先解释所需输入与类型转换语法；题面明确格式、范围、样例、输出比较方式和时间限制。
- 第12题已在题目前讲解 `split()`、序列解包和逐项类型转换，开始采用单行多参数输入；后续题目按平台习惯与题意安排输入格式，第10、11题保留原来的两行输入。
- 每道新题只添加一个 `评测/题库/题号.json`，把设置和多组 `input`、`expected` 文本集中在其中，不拆成大量 `.in`、`.out`；用通用 `评测/judge.py` 评测。
- 先独立核验测试答案，覆盖样例、正常情况和题意内的边界值；不得改动答案迁就学生程序。
- 检查时运行评测器，并继续审阅实现，分开反馈测试通过与知识掌握；不改动学生答案。
- 用 `评测使用说明.md` 说明操作；新题移动时也要修正题库 JSON 中的作答路径；测试数量和边界覆盖不因合并文件而减少。
- VS Code 的 Ctrl+Shift+B 和“评测当前题目”运行配置通过 `judge.py --file` 自动识别当前文件；新增题库配置后必须兼容该入口。
