## 一、核心知识点系统整合

### 1. 标准输入、多分隔拆分与数字鲁棒校验（课件 `lec4` /《快速上手》1.6 /《往年题》）
- **`input()` 读取原则**：`input()` 永远返回**字符串 `str`**；评测与考场做题括号内**不要加提示文字**，否则提示文字会直接进入比对输出导致 WA。
- **拆分与清理**：
  - 空白分隔：`a, b = input().split()`（自动按任意长度空格/制表符切分并去除首尾空白，解包后无需再 `.strip()`）；
  - 逗号分隔（考场真题高频）：`a, b, c = input().split(",")`；
  - 连带单位串：用切片区分不同长度后缀（如 `"Euro"` 切 `[:-4]` / `[-4:]`，`"RMB"` 切 `[:-3]` / `[-3:]`），勿漏掉无效后缀兜底（`format error`）。
- **类型转换与为什么不滥用 `eval(input())`**：
  - 工程和规范评测统一用明确语义转换：`int()`、`float()`、`str()`、`complex()`。
  - 课件和 MOOC 常见 `eval(input())`，但它会直接把输入当作 Python 代码执行——遇到文字报 `NameError`、遇到 `"10**2"` 会算出 `100` 而不拦截，且真实系统有注入执行风险。
  - **数字级联校验（第 27 题真题点）**：按 **`int(s)` → `float(s)` → `complex(s)`** 顺序 `try / except ValueError` 依次尝试，三者全失败即非法（可精准接受纯十进制数与复数，并自动拒收 `"10**2"`、`"0b10"` 和非数字文本）。
- **类型检查 `type()` vs `isinstance()`**：
  - `type(x)` 返回精确类型；`isinstance(x, (int, float))` 判断是否属于给定类型（支持元组传多类型，面向对象中还会识别子类）。
  - `isinstance(...)` 本身返回布尔值，直接写 `if isinstance(x, float):`，不用画蛇添足写 `is True`；若变量已确认经 `float()` 转出且未抛 `ValueError`，则它必定已是 `float`。

### 2. 异常处理入门：`try / except / else / finally`（课件 `lec4` /《快速上手》3.8）
- **常见内建异常速览**：`ValueError`（值不合法如 `int("abc")`、`math.sqrt(-1)`）、`NameError`（变量未定义）、`TypeError`（类型不匹配如 `'a' + 1`、`'py'[1.5]`）、`IndexError`（下标越界）、`ZeroDivisionError`（除数为 0）、`SyntaxError`（语法错误，运行前即报错）。
- **指定具体异常 vs 裸 `except:`（高频概念考题）**：
  - 应当写 **`except ValueError:`**（可同时写多个 `except` 或元组 `except (ValueError, ZeroDivisionError):`）。
  - **绝不推荐裸 `except:`**：裸 `except:` 会吞掉你自己的代码 Bug（如拼错变量名的 `NameError` 会被默默当成“输入错误”屏蔽，极难排查），还会拦截 `KeyboardInterrupt`（`Ctrl+C`）和 `SystemExit` 退出信号。
- **可选扩展子句（课件 `control-structures.ipynb`）**：`try` 无异常时执行 `else:` 块；无论是否发生异常、最后清理收尾都会执行 `finally:` 块。
- **前置初始化铁律（第 21 题实战教训）**：
  - 一旦 `try` 内某行触发异常，会直接跳去 `except`，`try` 块中该行之后的赋值语句**不会执行**！
  - 规范做法：进入 `try` 前先把变量初始化为 **`None`**（或 `False`），之后只需一层 `if val is not None:` 即可判断，避免既设布尔标志又做冗余判断。

### 3. 布尔值、四大类运算符与短路求值（课件 `lec4` /《从入门到实践》5.1～5.2 /《基础教程》5.4）
- **布尔值与真值表（Truthiness）**：布尔型 `bool` 只有 `True` 和 `False`；在条件上下文中，**空对象与零值均为假**（`False`、`None`、`0`、`0.0`、`""`、`[]`、`{}`、`set()`），其余非零数/非空容器（包括 `"0"`、`" "`）均为真。
  - **关键防坑**：当 `0` 是合法有效输入时，判断“是否有效”必须写 **`if val is not None:`**，绝不能写 `if val:`。
- **四类核心运算符**：
  1. **比较运算符**：`==`、`!=`、`<`、`<=`、`>`、`>=`（支持链式 `36.0 <= t <= 37.3`）。注意 `=` 是赋值、`==` 是判等，条件里误写 `if a = b:` 会直接报 `SyntaxError`。
  2. **成员运算符**：`in` / `not in`（区分大小写，判断子串或容器成员，如 `'@' in word`、`unit in ("c", "f")`）。
  3. **身份运算符 `is` / `is not` vs `==`（高频必考！）**：
     - `==` 比较两个对象的**值**是否相等；`is` 比较两者是否为内存中**同一个对象**（等价于 `id(a) == id(b)`）。
     - 小整数或短字符串有时因解释器缓存看似 `is` 为 `True`，但大整数或两个相同内容的列表（`[1, 2] is [1, 2]`）为 **`False`**。
     - **规范**：**`is` / `is not` 仅用于比较单例（尤其是 `val is None` / `val is not None`）**；比较数字和字符串一律用 `==` / `!=`。
  4. **逻辑运算符与优先级**：
     - 优先级：**`not` > `and` > `or`**（低于比较/算术运算符），复杂组合务必加括号明确顺序（如闰年 `(year % 4 == 0 and year % 100 != 0) or (year % 400 == 0)`）。
     - **短路求值（Short-circuit Evaluation）**：
       - `A and B`：若 `A` 为假，直接得出 `False`，**根本不计算 `B`**；
       - `A or B`：若 `A` 为真，直接得出 `True`，**根本不计算 `B`**。
       - 典型应用：前置守卫（`if s and s[0] == "a":`、`if valid and x > 0:`），靠短路保护后半段不报 `IndexError` 或 `NameError`。

### 4. 条件分支结构、嵌套 vs 独立、三元表达式与提前终止（课件 `lec4` /《从入门到实践》5.3～5.4）
- **四种分支形态**：
  1. **单分支**：`if cond:`（条件成立才执行）；
  2. **双分支**：`if cond: ... else: ...`；
  3. **三元条件表达式（紧凑二选一）**：`<值1> if <条件> else <值2>`（如 `sign = 1 if n >= 0 else -1`）；
  4. **多分支 `if / elif / ... / else`**：自上而下判断，**命中第一条成立的分支后，后面所有 `elif` 和 `else` 全部跳过**。
- **分支顺序与区间设计（课件 PM2.5 / BMI 案例）**：
  - 递增区间判断（如 `pm < 0` → `pm < 35` → `pm < 75` → `else`）天然排除了上一档范围，不必重复写 `35 <= pm < 75`；
  - 若把宽范围放在前面（如 `pm < 75` 放在 `pm < 35` 前），小值会被提前吞掉；
  - **“任一无效”兜底（如 `CHECK_RETRY` / `INVALID_RECORD`）必须放在最顶层且用 `or` 连接**，确保不带着未定义变量跌进后续判断。
- **互斥 `if/elif/else` vs 独立多个 `if`（第 22 题核心）**：
  - **互斥分类**（一个事物只可能属于一档，如成绩 A/B/C、运费重量档）→ 用 **`if / elif / else`**（若错写成并列 `if` 会连续命中多档重复输出）；
  - **可叠加独立规则**（如先加急费 → 再会员 8 折 → 再满足门槛减 5 元；后一步基于前一步更新后的新变量继续结算）→ 用**并列多个 `if`**（若错写成 `elif` 则命中第一条后就会跳过后续折扣）。
- **嵌套分支与状态标志传递（第 24 题核心）**：
  - 外层大条件成立后，内层缩进再细判；
  - 当两项优惠互相冲突且前者可能“带了卡但未触发条件而回退”（如 `NIGHT` 卡在白天失效后仍允许用现金券），必须记录实际生效状态 **`pass_applied`**，而不能只看输入字符串 `pass_type == "NONE"`。
- **满足条件提前停止程序（考场/脚本实用）**：
  - **方法 1**：`import sys` 后先 `print("INVALID_RECORD")` 再调用 **`sys.exit(0)`**（切勿传字符串 `sys.exit("INVALID_RECORD")`，那会导致非零退出码并输出到 `stderr` 被判 `RE`；也别放在裸 `except:` 的 `try` 里）；
  - **方法 2（通常更推荐）**：用 `if not valid: print(...) else: ...` 包裹后续主体逻辑；
  - **函数模板填空**：若外层模板写了 `print(func(_x))`，函数体末尾必须 `return 结果` 交回数据，勿在内部 `print` 后漏 `return`（否则多印一行 `None`）。

#### 题型 A：概念辨析与输出预测

**A1.** 下面 4 组代码输出什么？哪些会跳过计算而不报错？
```python
x = None
a, b = 1000, 1000
print(x is None, a == b)
```

**A2.** 下面代码执行后一共打印几行、分别是什么？

```python
def add_one(x):
    print(x + 1)

print(add_one(5))
```

**A3.** 若输入 `s = "abc"`、`k = 0`，但代码只写了 `if not s or k > len(s): print("ERROR") else: print(s[k - 1] == s[-1])`（漏了 `k < 1`），会打印什么？为什么比直接报 `IndexError` 更隐蔽？

```python
if pm < 0: print("INVALID")

else: print("BAD")

# 版本 2（全改成独立 if）
if pm < 35: print("GREAT")
if pm < 75: print("OK")
```

#### 题型 B：Bug 找茬与改错

**B1.（目标：读两行整数，各自成功则输出数值，都成功输出之和，否则输出 `CANNOT_ADD`）**
```python
try:
    a = int(input().strip())
    ok_a = True
except ValueError:
    print("NOT_INT")
try:
    b = int(input().strip())
    ok_b = True
except ValueError:
    print("NOT_INT")

if ok_a and ok_b:
    print(a + b)
else:
    print("CANNOT_ADD")
```

**B2.（目标：两项检验任一无效输出 `RETRY`；否则先按满 80 封顶，再对封顶后满 50 的订单减 10 元并输出实付）**
```python
price = 95
valid_a = False
valid_b = True

if valid_a:
    status = "OK"

if not valid_a and not valid_b:
    print("RETRY")
elif status != "OK":
    print("WAIT")
else:
    final = price if price <= 80 else 80
    if price >= 50:
        final = price - 10
    print(final)
```

**B3.（目标：输入时间 `hhmm` 如 `1260` 检验合法性；若输入 `"exit"` 先输出 `"BYE"` 再正常结束评测）**
```python
import sys
t = input().strip()
if t == "exit":
    sys.exit("BYE")
code = int(t)
if code // 100 > 23 or code % 100 > 60:
    print("INVALID")
```

### 题型 A 答案与解析
- **A1**：`True True` / `False`（短路求值跳过 `1/0`）/ `True`（短路求值跳过 `1/0`）/ `False True False False`（`"0"` 是非空串，布尔值为 `True`）。

### 题型 B 答案与解析
- **B1**：任一行转失败时 `ok_a` 或 `ok_b` 未定义，第 12 行 `NameError`。应在 `try` 前初始化 `a = None`、`b = None`，最后只需写 `if a is not None and b is not None:`。
- **B2**（共 3 处错）：
  1. “任一无效”应写成 **`if not valid_a or not valid_b:`**，当前 `and` 导致只错一边时跳过并跌入 `elif status != "OK"` 直接 `NameError: name 'status' is not defined`；
  2. 第 13～14 行判断和减法误用了原价 `price`，把第 12 行的 `80` 元封顶覆盖成了 `85`（`95 - 10`）；应改用 `if final >= 50: final -= 10`。
- **B3**（共 3 处错）：
  1. `sys.exit("BYE")` 会返回非零退出码并在 `stderr` 打印导致评测判 **`RE`**，应写 `print("BYE"); sys.exit(0)`；
  2. `code % 100 > 60` 漏了 `=`，会放过 `1260`，应改 `>= 60` 并补充 `code < 0` 检查，同时把 `int(t)` 放进 `try/except ValueError`。

### 题型 C 答案与解析
1. `eval("10**2")` 把字符串当 Python 表达式算出 `100`（且存在任意代码执行风险）；`int → float → complex` 只做纯数字字面量解析，遇到 `"10**2"` 或 `"0b10"` 都会抛 `ValueError` 被拦截。
2. 当合法数字恰好为 **`0`** 时，`bool(0)` 是 `False`，`if x:` 会误判为转换失败；必须用 `if x is not None:`。当用户持有 `NIGHT` 卡却在白天刷卡时，卡并未生效（`pass_applied == False`），回退后依然可用现金券；若只看 `pass_type == "NONE"` 就会误杀回退后的现金券资格。
