# 本地自动评测使用说明

从第10题开始，题目使用真实的标准输入。你在题目文件中作答，评测器负责输入测试数据和检查输出，不需要逐组手动输入。每题的设置、输入和预期输出集中放在一个 JSON 文件中。

## 第一次使用

1. 打开 [第10题：分组与剩余](基础题/数字与运算/10_分组与剩余.py)，阅读注释中的题面，在末尾作答。
2. 按 **Ctrl+S** 保存。
3. 保持题目的 `.py` 文件为当前活动标签，按 **Ctrl+Shift+B** 自动评测；也可以告诉我“检查第10题”。

## 在 VS Code 中一键评测（推荐）

VS Code 需要打开当前仓库的 **`python` 文件夹**作为工作区，才能读取这里的 `.vscode` 配置。配置使用本机已安装的 Python 3.14。

- **最快的方式**：打开题目 → Ctrl+S 保存 → Ctrl+Shift+B。终端自动显示评测结果，无需输入题号或命令。
- **点击运行**：打开左侧“运行和调试”（Ctrl+Shift+D），选择 **“评测当前题目（自动识别）”**，保持题目文件打开并激活，点击绿色 ▶。选好配置后也可按 F5。
- **菜单入口**：终端 → 运行生成任务 → 评测当前题目。

评测器根据当前文件和题库配置自动识别题号，新题接入后可继续使用相同快捷键。第1～9题尚未接入文件评测，打开它们会显示“尚未接入评测”。

右上角 Python 扩展或 Code Runner 的普通 Run 按钮仍直接运行当前程序，适合手动输入调试；自动跑全部测试点请使用上面的评测入口。

如果快捷键没有出现评测任务，先确认打开的工作区是 `python` 文件夹。如果显示“文件不存在或已移动”，请从路线图重新打开新路径的题目；旧路径的标签页可以关闭。

## 终端命令方式（可选）

以下命令的工作目录是当前仓库的 `python` 文件夹，也就是能看到“用vscode的插件学”和“资料”的目录：

```powershell
py -3 ".\用vscode的插件学\评测\judge.py" 10
```

最后的 `10` 是题号。后续接入新题后，替换这个数字即可。

如果终端找不到 `py`，可以使用已安装的 Python 解释器。本机已核验的路径如下：

```powershell
& "C:\Users\EasonG\AppData\Local\Programs\Python\Python314\python.exe" ".\用vscode的插件学\评测\judge.py" 10
```

评测器只使用 Python 标准库，不需要安装第三方包。它会用启动自己的解释器运行你的代码。

## 如何写输入代码

- `input()` 每调用一次就读取一行，得到的是字符串。
- `int(input())` 读取一行并转成整数。例如 `age = int(input())`。
- 一行有多个参数时，先用 `input().split()` 拆分并解包，再逐项转换；具体讲解见 [第12题：团购账单](综合题/数字与运算/12_综合_团购账单.py)。不带参数的 `split()` 能处理连续空格和制表符。
- 按题面顺序读取数据，不要把测试文件内容直接写进程序。
- 不要使用 `input("请输入……")`，也不要打印提示或调试文字；这些内容会被当成答案的一部分。
- 直接运行作答文件时，程序等待输入是正常现象；输入一行后按回车。运行评测器时，输入由文件自动提供。

## 如何读评测结果

- **AC**：该测试点通过。
- **WA**：答案不符合要求。评测器显示预期输出与实际输出，换行会显示为 `\n`。
- **RE**：运行错误。查看后面的异常信息及代码行号，例如类型转换错误或读取次数过多。
- **TLE**：超过该题的单个测试点时间限制；第10题为每点2秒。
- **CE**：代码有语法错误，尚未开始测试。
- **评测配置或运行环境错误**：文件、解释器或题库配置存在问题，可以把这条信息告诉我。

例如 `8/8 通过` 表示第10题的8个测试点全部通过，第11题则有14个测试点。空白作答文件会得到 WA，这属于尚未作答的正常结果。

第10题按空白分隔后的内容比较：`4 3` 和分两行输出相同，但 `4.0` 与 `4` 不同；额外标签和调试文字不被忽略。第11题同样忽略空白差异，但必须输出两位小数，例如 `62.80` 不能省略末尾的 `0`。每题会单独说明比较方式。

## 推荐做题流程

1. 先读题，明确输入、输出和数据范围。
2. 在作答文件中编程并保存。
3. 按 Ctrl+Shift+B 评测，查看未通过的测试点，修改保存后再次评测。
4. 全部通过后告诉我检查，我会继续看思路、是否写死答案、实现方式与边界情况。

保存文件本身不会自动触发评测，需要按快捷键、点击评测入口、运行命令或告诉我检查。评测器也不会改动你的作答文件或自动修改路线图；由我检查后更新学习进度。

## 文件在哪里

- 作答文件仍放在“难度 / 知识点”目录中，例如 [第10题](基础题/数字与运算/10_分组与剩余.py)。
- [评测器](评测/judge.py) 是通用工具，不是你当前需要学习或修改的题目。
- [第10题测试](评测/题库/10.json) 和 [第11题测试](评测/题库/11.json) 各只占一个文件。
- 每个 JSON 同时包含作答文件路径、比较方式、时间限制，以及 `cases` 中的全部测试输入和预期输出。
- `input` 和 `expected` 都是文本，里面的 `\n` 表示换行；程序直接把输入文本送给你的 `input()`，不生成临时输入输出文件。
- 新增测试点只需增加 JSON 中的一条记录，不增加文件数量；作答文件和评测工具仍独立保存。
- 这些是本地公开测试；通过现有测试仍需结合代码审阅判断通用性。
