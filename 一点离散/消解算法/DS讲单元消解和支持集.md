# 单元消解与支持集策略详解

下面脱离具体编程题目，从**逻辑学理论**的角度把这两个概念讲清楚。

***

# 一、单元消解（Unit Resolution）

## 1.1 什么是单元子句

在消解原理中，子句是若干文字的析取。按文字个数分类：

| **类型** | **文字个数** | **示例**            | **含义**   |
| ------ | -------- | ----------------- | -------- |
| 空子句 □  | 0        | `□`               | 恒假，矛盾    |
| 单元子句   | 1        | `{p}`、`{¬q}`      | 强制某个文字为真 |
| 二元子句   | 2        | `{p, ¬q}`         | 两个文字的析取  |
| 一般子句   | n        | `{p, ¬q, r, ...}` | n 个文字的析取 |

**单元子句的特殊性**：它只含一个文字，所以它**不给任何选择余地**。`{p}` 意味着 `p` 必须为真，`{¬q}` 意味着 `q` 必须为假。

这种"强制性"是单元消解威力的来源。

## 1.2 单元消解规则

普通消解规则：

```
C₁ ∨ L        C₂ ∨ ¬L
──────────────────────
      C₁ ∨ C₂
```

单元消解是它的特例：当 `C₁` 为空（即一个子句就是单元子句 `{L}`）时：

```
{L}        C₂ ∨ ¬L
──────────────────
       C₂
```

用自然语言说：

> **如果 `L` 已经被断言为真，那么任何含 `¬L` 的子句，其中 `¬L` 必然为假，所以可以把这个 `¬L` 删掉，剩下的部分必须为真。**

## 1.3 具体例子

假设子句集：

```
{ p }
{ ¬p, q }
{ ¬q, r }
{ ¬r }
```

逐步单元消解：

**第 1 步**：`{p}` 和 `{¬p, q}` 消解

```
p 为真 → ¬p 为假 → {q} 必须为真
```

得到 `{q}`。

**第 2 步**：`{q}` 和 `{¬q, r}` 消解

```
q 为真 → ¬q 为假 → {r} 必须为真
```

得到 `{r}`。

**第 3 步**：`{r}` 和 `{¬r}` 消解

```
r 为真，但 {¬r} 要求 r 为假 → 矛盾！
```

得到空子句 `□`。

**结论**：子句集不可满足。

整个过程中，每一步消解都产生一个**更短的子句**，而且产生的新子句又是单元子句，可以继续消解。这就是单元消解的**链式反应**特性。

## 1.4 单元消解为什么重要

### （1）它是一条"确定性"路径

普通消解面临一个选择：从众多子句中挑哪两个来消解？这个选择空间巨大。而单元消解**没有选择余地**——只要有单元子句，就必须和含其否定的子句消解。这是一条**确定性**的推理链。

### （2）它是 DPLL 算法的核心

现代 SAT 求解器（如 MiniSat、Z3、Cadical）的核心算法 DPLL（Davis-Putnam-Logemann-Loveland）中，**单元传播（Unit Propagation）** 是最关键的一步：

```
while 存在单元子句 {L}:
    把 L 标记为真
    删除所有含 L 的子句（因为已经被满足）
    从所有含 ¬L 的子句中删除 ¬L
    if 产生空子句: 返回 UNSAT
```

这就是单元消解在工程上的实现。它能在搜索树展开之前，**免费地**大幅简化问题。

### （3）它不完备

**重要警告**：单元消解本身**不完备**。有些不可满足的子句集，单靠单元消解推不出空子句。

反例：

```
{ p, q }
{ p, ¬q }
{ ¬p, q }
{ ¬p, ¬q }
```

这个子句集不可满足（穷举 p、q 四种取值都矛盾），但**没有任何单元子句**，所以单元消解根本无法启动。

因此单元消解必须和普通消解配合使用。

## 1.5 单元消解总结

| **特性** | **说明**                      |
| ------ | --------------------------- |
| 规则     | `{L}` 与含 `¬L` 的子句消解，删去 `¬L` |
| 效果     | 子句长度严格递减                    |
| 优势     | 确定性、链式反应、极快                 |
| 局限     | 不完备，无单元子句时无法启动              |
| 应用     | DPLL 的单元传播、SAT 求解器预处理       |

# 二、支持集策略（Set-of-Support Strategy）

## 2.1 动机：普通消解的空间爆炸

普通消解允许**任意两个子句**互相消解。假设子句集有 n 个子句，每轮两两消解的组合数是 O(n²)。更糟的是，每轮都会产生新子句，子句集不断膨胀，下一轮组合数更大。

**问题**：所有消解都是必要的吗？

**答案**：不是。很多消解虽然逻辑上合法，但和"证明矛盾"这件事毫无关系。

## 2.2 核心思想

支持集策略把子句集分成两个部分：

* **支持集 S**：从**结论的否定**转化来的子句。它们代表"我们假设结论是错的"。
* **可用集 A**：从**前提**转化来的子句。它们代表"已知为真的事实"。

**消解限制**：

> **每次消解，至少有一个父辈子句来自支持集 S。**

新产生的消解式**加入支持集 S**（因为它仍然携带"结论否定"的假设）。

## 2.3 为什么这样合理？

反证法的逻辑结构：

```
前提 T  ⇒  结论 C
```

等价于证明：

```
T ∧ ¬C  不可满足
```

在这个合取式中：

* `T` 是"已知事实"（可用集 A）
* `¬C` 是"假设"（支持集 S）

矛盾从何而来？矛盾来自 **`¬C` 和 `T`（或其推论）的碰撞**。纯粹的 `T` 内部消解不会产生矛盾（因为 `T` 本身是可满足的，前提无矛盾），纯粹的 `¬C` 内部消解也不会产生矛盾（因为结论的否定单独也是可满足的）。

**只有让"假设"和"事实"相互作用，才能推出矛盾。**

支持集策略的规则"每次消解至少一个来自 S"，正是把搜索严格限制在这种"假设 vs 事实"的交互上。

## 2.4 具体例子

证明：`(p → q) ∧ (q → r) ⇒ (p → r)`

**前提 T**：

```
¬p ∨ q
¬q ∨ r
```

这两条放入**可用集 A**。

**结论的否定 ¬C**：

```
p
¬r
```

这两条放入**支持集 S**。

初始：

```
A = { ¬p ∨ q,  ¬q ∨ r }
S = { p,  ¬r }
```

**第 1 轮消解**（每次至少一个来自 S）：

* `{p}`（S）和 `{¬p ∨ q}`（A）消解 → `{q}`，加入 S。
* `{¬r}`（S）和 `{¬q ∨ r}`（A）消解 → `{¬q}`，加入 S。

现在：

```
A = { ¬p ∨ q,  ¬q ∨ r }
S = { p,  ¬r,  q,  ¬q }
```

**第 2 轮消解**：

* `{q}`（S）和 `{¬q}`（S）消解 → `□`。

推出空子句，证明完毕。

**对比普通消解**：普通消解可能还会去消解 `{¬p ∨ q}` 和 `{¬q ∨ r}`（两个都来自 A），得到 `{¬p ∨ r}`，这个子句对证明毫无帮助，白白浪费计算。

## 2.5 支持集策略的完备性

**重要定理**：如果子句集 `A ∪ S` 不可满足，且 `A` 本身可满足，那么**只使用"至少一个父辈来自 S"的消解**，一定能推出空子句。

这个定理保证了支持集策略是**反驳完备**的——只要原公式真的不可满足，就一定能通过这种受限的消解找到矛盾。

**前提条件**：`A` 本身必须可满足。这在实际中通常成立，因为前提 `T` 一般不应该是自相矛盾的。

## 2.6 支持集策略总结

| **特性** | **说明**                   |
| ------ | ------------------------ |
| 规则     | 每次消解至少一个父辈子句来自支持集 S      |
| 支持集 S  | 结论的否定转化来的子句              |
| 可用集 A  | 前提转化来的子句                 |
| 新子句归属  | 加入 S                     |
| 优势     | 大幅缩小搜索空间，避免无关消解          |
| 完备性    | 在 A 可满足的前提下是反驳完备的        |
| 应用     | 定理证明、逻辑编程（Prolog）、SAT 求解 |

# 三、两者的对比与联系

## 3.1 对比

| **维度**   | **单元消解**             | **支持集策略**             |
| -------- | -------------------- | --------------------- |
| **限制方式** | 限制子句的**形式**（必须是单元子句） | 限制子句的**来源**（至少一个来自 S） |
| **搜索方向** | 由单元子句驱动的确定性链         | 从结论否定出发的定向搜索          |
| **完备性**  | 不完备                  | 反驳完备（A 可满足时）          |
| **速度**   | 极快（线性链式）             | 较快（搜索空间缩小）            |
| **适用场景** | 有单元子句时               | 反证法证明                 |
| **失效场景** | 无单元子句                | A 不可满足                |

## 3.2 联系

两者**正交**，可以叠加使用：

```
while True:
    # 阶段 1：单元消解（快速通道）
    while 存在单元子句:
        执行单元消解
        if 推出空子句: return UNSAT
    
    # 阶段 2：支持集策略消解（主搜索）
    选择一个 S 中子句和一个 A∪S 中子句
    执行消解
    if 推出空子句: return UNSAT
    if 没有新子句产生: return SAT
```

**实际系统**（如 Prolog 的 SLD 消解、SAT 求解器）通常同时使用这两种策略，再加上其他启发式（如最短子句优先、MOMS 策略等）。

## 3.3 一个统一视角

从**搜索空间**的角度看：

* **普通消解**：在"所有子句对"构成的空间中搜索。空间最大。
* **支持集策略**：在"至少一个来自 S 的子句对"构成的空间中搜索。空间缩小。
* **单元消解**：在"单元子句驱动的链"上搜索。空间最小，但可能找不到解。
* **两者结合**：先用单元消解快速简化，再用支持集策略搜索剩余空间。

这就是现代自动定理证明和 SAT 求解的基本框架。

***

# 四、一句话总结

> **单元消解**：利用单元子句的强制性，做确定性的链式推理，快速简化或发现矛盾。
>
> **支持集策略**：利用反证法的结构，强制每次消解都涉及"结论的否定"，把搜索限制在真正可能产生矛盾的路径上。

两者都是**用逻辑结构换搜索效率**的经典范例。
