# 第 5 讲 · AI Taking Action：从「写字」到「动手」

> 官方英文标题：**AI Taking Action**　｜　斯坦福 CS193T（2026 秋）
> 课程页：https://web.stanford.edu/class/archive/cs/cs193t/cs193t.1272/lectures/05-agents/
> 视频：https://www.youtube.com/watch?v=I7zvCSGMkoc　｜　幻灯片：`../slides/05-agents.pdf`

### 这一讲在解决什么
第 3 讲结尾埋了一句警告：**一旦 AI 开始"动手"而不只是"写字"，prompt injection 会糟糕得多**。这一讲把这句话拆开。

### 官方描述（译）
先讲连接器（connectors）—— 让 AI 读你的邮件、日历、文件，并代表你行动。
然后说明**底下没有任何新东西**：还是第 1 讲那个下一个 token 预测，只是有时候生成一段特殊结构的文本，触发了动作。
接着建立真正自主工作的词汇：每个 agent 都在跑的"分析—行动—观察"循环，一个被良好定义的工具的七部分"解剖"，
以及专业级的 agentic 工作流技巧，比如"大象与金鱼"（elephant and goldfish）。
最后戴上悲观的安防帽子：对你设计的每一个 agent，**最坏能发生什么？是谁的权限让它成为可能的？**

### 关键概念
- **连接器**：agent 的手。没有连接器，它只能建议；有了连接器，它能替你点确认
- **分析—行动—观察**：agent 的最小循环。三步里最容易被省掉的是"观察"——也就是看结果对不对
- **七要素解剖**：一个规格清楚的 agent 应该写清的部分（目标、可用工具、权限边界、成功判据、失败处理、何时停下、谁来兜底）
- **大象与金鱼**：在一个长对话里把设计文档写完（大象有记忆），再丢给一个全新会话、零记忆的实例（金鱼）去检查它能不能独立成立 —— 能过金鱼这关，说明文档本身站得住
- **权限即风险**：agent 能造成多大破坏，等于你给它的权限有多大。最坏情况分析要从"它拿了谁的钥匙"开始

### 看的时候留意
1. "底下还是 next-token prediction"那一段 —— 理解了这句，你就不会把 agent 当魔法
2. 最坏情况分析的提问方式：不是"它可能出错吗"，是"它出错时手里有什么"
3. 什么时候**不该**给 agent 连接器（这一讲有明确的标准）

### 自测
1. 画出一个 agent 的分析—行动—观察循环，标出你的场景里"观察"具体看什么。
2. 给一个你真实想自动化的任务，写它的七要素；哪一项你写不出来？为什么？
3. 用"最坏情况 + 谁的权限"框架，审一遍你已经在用的某个自动化。
