# 机场调度程序解析

下面从**算法设计逻辑**和**语法实现**两个角度拆解这个程序。

***

## 一、算法设计逻辑

### 1. 问题建模

这是一个**离散时间模拟**问题，时间以分钟为单位从 0 开始推进。每一分钟需要处理：

1. 输出当前时间；
2. 释放本分钟结束占用的跑道；
3. 读入本分钟新到达的降落/起飞请求；
4. 按“降落优先于起飞”的规则给空闲跑道分配飞机；
5. 判断模拟是否结束；
6. 时间加 1。

程序采用**时间驱动**方式，而不是事件驱动方式。每个时间单位扫描所有跑道，适合题目规模。

***

### 2. 核心数据结构

```cpp
struct Plane {
    int id;
    int requestTime;
};
```

* `id`：飞机编号，降落从 5001 开始，起飞从 0001 开始；
* `requestTime`：飞机请求调度的时间，用于计算等待时间。

```cpp
queue<Plane> landingQueue;
queue<Plane> takeoffQueue;
```

* 两个队列分别保存等待降落的飞机和等待起飞的飞机；
* 队列先进先出，保证同一类请求按到达顺序调度。

```cpp
vector<int> finishTime(R + 1, 0);
vector<int> busyTime(R + 1, 0);
```

* `finishTime[r]`：第 `r` 条跑道当前占用结束的时刻；
* `busyTime[r]`：第 `r` 条跑道累计被占用的时间；
* 下标从 1 开始，与跑道编号一致。

***

### 3. 主循环时序

每一分钟的执行顺序非常关键：

```text
输出 Current Time
→ 释放 finishTime == currentTime 的跑道
→ 如果机场未关闭，读入本分钟降落/起飞请求并入队
→ 给空闲跑道分配飞机
→ 判断是否结束
→ currentTime++
```

这个顺序保证了：

* 本分钟结束占用的跑道可以先释放；
* 本分钟释放的跑道可以分配给本分钟新请求或之前等待的飞机；
* 输出顺序符合题目示例：先输出当前时间，再输出空闲跑道，再输出被分配的飞机。

***

### 4. 跑道释放逻辑

```cpp
for (int r = 1; r <= R; ++r) {
    if (finishTime[r] > 0 && finishTime[r] == currentTime) {
        printf("runway %02d is free\n", r);
        finishTime[r] = 0;
    }
}
```

* 如果某跑道在 `currentTime` 结束占用，则输出 “runway xx is free”；
* 然后将 `finishTime[r]` 置 0，表示空闲；
* 因为每轮只处理当前分钟，所以不会漏掉释放事件。

***

### 5. 调度策略：降落优先

调度部分：

```cpp
for (int r = 1; r <= R; ++r) {
    if (finishTime[r] != 0) continue;

    Plane p;
    bool isLanding;

    if (!landingQueue.empty()) {
        p = landingQueue.front();
        landingQueue.pop();
        isLanding = true;
    } else if (!takeoffQueue.empty()) {
        p = takeoffQueue.front();
        takeoffQueue.pop();
        isLanding = false;
    } else {
        break;
    }

    int duration = isLanding ? landingTime : takeoffTime;
    finishTime[r] = currentTime + duration;
    busyTime[r] += duration;
    ...
}
```

逻辑要点：

1. 按跑道编号从小到大扫描；
2. 遇到空闲跑道时：
   * 只要降落队列非空，就优先取降落飞机；
   * 只有降落队列为空时，才取起飞飞机；
3. 分配后设置该跑道的结束时刻；
4. 累计跑道占用时间；
5. 输出飞机分配信息。

这种写法实现了**全局降落优先**：

所有空闲跑道都会先把降落队列中的飞机分配完，之后才会分配起飞飞机。

***

### 6. 等待时间统计

分配飞机时：

```cpp
if (isLanding) {
    totalLandingWait += currentTime - p.requestTime;
    ++landingCount;
    ...
} else {
    totalTakeoffWait += currentTime - p.requestTime;
    ++takeoffCount;
    ...
}
```

等待时间定义为：

```text
被分配跑道的时刻 - 请求时刻
```

若请求当分钟就分配，等待时间为 0。

最后统计平均值时使用 `double`，避免整数除法。

***

### 7. 关闭与结束条件

输入 `-1 -1` 时：

```cpp
if (landNum < 0 && takeoffNum < 0) {
    closed = true;
}
```

关闭后不再接受新请求，但队列中剩余飞机继续调度。

结束条件：

```cpp
if (closed && landingQueue.empty() && takeoffQueue.empty()) {
    bool allIdle = true;
    for (int r = 1; r <= R; ++r) {
        if (finishTime[r] > currentTime) {
            allIdle = false;
            break;
        }
    }

    if (allIdle) {
        simulationTime = currentTime;
        break;
    }
}
```

即必须同时满足：

1. 机场已关闭；
2. 降落队列为空；
3. 起飞队列为空；
4. 所有跑道都不再被占用。

此时记录模拟结束时间并退出循环。

***

### 8. 最终统计

程序输出：

* 模拟时间；
* 降落平均等待时间；
* 起飞平均等待时间；
* 每条跑道累计占用时间；
* 跑道平均占用百分比。

平均等待时间：

```cpp
double avgLandingWait =
    landingCount ? (double)totalLandingWait / landingCount : 0.0;
```

跑道平均占用百分比：

```cpp
double averageBusy = R ? (double)totalBusy / R : 0.0;
double busyPercentage =
    simulationTime > 0 ? averageBusy * 100.0 / simulationTime : 0.0;
```

等价于：

```text
所有跑道总占用时间 × 100 / (跑道数 × 模拟时间)
```

## 二、语法实现角度

### 1. 结构体与容器

```cpp
struct Plane {

    int requestTime;

```

用于封装飞机编号和请求时间。

```cpp
queue<Plane> landingQueue;

```

使用 STL 的 `queue` 实现先进先出。

***

### 2. 输入处理

```cpp
if (scanf("%d%d%d", &R, &landingTime, &takeoffTime) != 3) return 0;
```

先读入跑道数、降落占用时间、起飞占用时间。

每分钟读入：

```cpp
if (scanf("%d%d", &landNum, &takeoffNum) != 2) {
    closed = true;
}
```

通过检查 `scanf` 返回值处理输入结束或异常情况。

***

### 3. 格式化输出

```cpp
printf("Current Time: %4d\n", currentTime);
```

* `%4d`：宽度 4，右对齐，不足补空格；
* 与题目要求的 `%4d` 一致。

```cpp
printf("runway %02d is free\n", r);
```

* `%02d`：宽度 2，不足补 0。

```cpp
printf("airplane %04d is ready to land on runway %02d\n", p.id, r);
printf("airplane %04d is ready to takeoff on runway %02d\n", p.id, r);
```

* 飞机编号用 `%04d`；
* 跑道编号用 `%02d`。

统计输出：

```cpp
printf("average waiting time of landing: %4.1f\n", avgLandingWait);
printf("average waiting time of takeoff: %4.1f\n", avgTakeoffWait);
printf("runway %02d busy time: %4d\n", r, busyTime[r]);
printf("runway average busy time percentage: %4.1f%%\n", busyPercentage);
```

* `%4.1f`：保留 1 位小数；
* `%%`：输出百分号。

***

### 4. 循环与分支控制

主循环：

```cpp
while (true) {
    ...
    if (结束条件) break;
    ++currentTime;
}
```

调度循环：

```cpp
for (int r = 1; r <= R; ++r) {
    if (finishTime[r] != 0) continue;
    ...
    if (landingQueue.empty() && takeoffQueue.empty()) break;
}
```

* `continue` 跳过被占用跑道；
* `break` 在没有待分配飞机时提前结束跑道扫描。

注意这里的 `break` 只跳出当前 `for` 循环，不会跳出主 `while`。

***

### 5. 类型转换与精度

```cpp
double avgLandingWait =
    landingCount ? (double)totalLandingWait / landingCount : 0.0;
```

* `totalLandingWait` 使用 `long long`，避免大量飞机累计等待时间溢出；
* 计算平均值时强制转换为 `double`，避免整数除法丢失小数。

***

### 6. 变量初始化与边界保护

```cpp
int nextLandingId = 5001;
int nextTakeoffId = 1;
bool closed = false;
int currentTime = 0;

```

编号、关闭状态、当前时间均初始化。

统计中还有：

```cpp

```

用于避免除零。

## 三、总体评价与注意点

### 优点

1. **时序清晰**：释放跑道、读请求、调度、结束判断顺序正确；
2. **降落优先实现简洁**：每个空闲跑道先看降落队列，再看起飞队列；
3. **数据结构选择合理**：`queue` 保证同类请求顺序，`vector` 方便按跑道编号访问；
4. **输出格式严格**：`%4d`、`%02d`、`%04d`、`%4.1f` 与题目一致；
5. **统计完整**：等待时间、占用时间、占用百分比均正确累计。

### 需要注意的边界

1. 程序假设降落/起飞占用时间为正数。若占用时间为 0，当前释放逻辑会导致该跑道下一分钟才释放；
2. 关闭条件按题意是“两者都小于 0”，若输入只有一个负数，程序不会关闭；
3. 程序采用每分钟扫描所有跑道的模拟方式，复杂度约为 `O(模拟时间 × 跑道数)`，本题规模下足够；
4. 等待时间在分配跑道时计算，因此等待时间不包括飞机占用跑道之后的时间，符合题意。

整体上，该程序是一个结构清晰的**时间驱动队列模拟**：用两个 FIFO 队列维护等待飞机，用跑道结束时间数组维护资源占用，通过每分钟扫描实现释放与调度，最后统一统计输出。

## 一、核心逻辑：离散时间模拟 + 资源分配

整个问题本质上是：

> 在一个**离散时间轴**上，有一组**可复用资源（跑道）**，每时刻有**两类带优先级的任务（降落、起飞）**&#x5230;达，任务是**不可抢占**的、占用资源固定时长，求按优先级调度下的等待时间与资源利用率。

程序采用**时间驱动模拟（time-driven simulation）**，而非事件驱动。每一分钟做一次完整的状态推进：

```
时间 t：
  ① 结算：t 时刻到期的跑道占用 → 释放
  ② 到达：t 时刻新请求 → 入队
  ③ 调度：空闲跑道 + 等待队列 → 分配
  ④ 终止判断
  t ← t + 1
```

这四步的顺序是核心逻辑的关键，它定义了系统状态的**转移函数**：

| **步骤** | **作用**                    | **为什么必须在这个位置**          |
| ------ | ------------------------- | ----------------------- |
| ① 释放   | 把 `finishTime == t` 的跑道置空 | 本分钟就能被重新分配，不浪费一分钟       |
| ② 到达   | 新请求入队                     | 本分钟到达的飞机有机会本分钟就分配（等待=0） |
| ③ 调度   | 空闲跑道按优先级出队                | 使用①释放的和原本就空的跑道          |
| ④ 终止   | 关闭 + 队列空 + 无占用            | 保证所有遗留任务都处理完            |

**核心状态**由三部分组成：

* 跑道状态：每条跑道的“何时空闲”（`finishTime`）；
* 等待队列：两类任务各自的 FIFO；
* 累计量：编号生成器、等待时间总和、占用时间总和。

***

## 二、数据结构：三类状态三种容器

程序里有三种本质不同的状态，各用最贴合其语义的数据结构：

### 1. 跑道状态 → 数组（按下标直接索引）

```cpp
finishTime[r]  // 跑道 r 的占用结束时刻，0 表示空闲
busyTime[r]    // 跑道 r 的累计占用
```

跑道是**固定数量、有编号、需要随机访问**的资源，所以用下标即跑道号的数组。每一分钟要“扫描所有跑道找到期者”和“扫描所有跑道找空闲者”，数组天然适合。

这里的关键抽象是：**用“结束时刻”而不是“是否占用”来表示跑道状态**。

如果只存 `bool occupied`，就需要额外一个计时器；存 `finishTime` 把“剩余时间”和“占用标记”合二为一——`finishTime == t` 即到期，`finishTime == 0` 即空闲。这是一个**状态压缩**技巧，让释放判断和空闲判断都变成一次比较。

### 2. 等待任务 → 两个 FIFO 队列

```cpp
queue<Plane> landingQueue;
queue<Plane> takeoffQueue;
```

同类任务之间是**纯先来先服务**，没有任何其他排序依据，所以 FIFO 队列是最自然的抽象。入队 O(1)、出队 O(1)。

**为什么分成两个队列而不是一个？**

因为调度规则是“降落整体优先于起飞”，而不是“先到先得”。用一个队列无法表达这种**跨类优先级**；分成两个队列后，优先级体现为“先从哪个队列取”，而队列内部仍保持到达顺序。这是把**优先级**和**时序**解耦。

### 3. 任务对象 → 只存必要信息

```cpp
struct Plane { int id; int requestTime; };
```

每个等待任务只需要两样东西：**身份（编号）** 和 **进入系统的时间（用于算等待）**。占用时长不是任务属性，而是任务**类别**属性（降落/起飞分别固定），所以不放进对象里，避免冗余。

***

## 三、算法策略：三个关键决策

### 1. 调度策略：全局降落优先 + 跑道顺序填充

调度时遍历跑道（编号从小到大），对每条空闲跑道：

```
if 降落队列非空 → 取降落
else if 起飞队列非空 → 取起飞
else → 没有可分配的，结束
```

这实现了**全局降落优先**：只要还有降落任务，任何空闲跑道都不会分给起飞。

等价说法：起飞任务只有在“降落队列为空”时才有机会被调度。

跑道按编号遍历，保证同一时刻多跑道分配时，飞机按跑道编号递增被安排——这既满足了输出顺序，也隐含了“低编号跑道优先使用”的确定性。

### 2. 等待时间：在“分配时刻”结算

```cpp
wait = currentTime - requestTime
```

等待时间在**任务出队并被分配跑道的那一刻**计算并累加。这是模拟中的标准做法：等待时间 = 服务开始时刻 − 到达时刻。

由于任务不会因为被分配而“回退”，这个累加只发生一次，统计量是**增量式**的，不需要保存所有任务的时间戳。

### 3. 终止条件：系统“静止”才结束

```cpp
closed && landingQueue.empty() && takeoffQueue.empty() && 所有跑道 finishTime <= currentTime
```

四个条件合起来表示：**不再有新输入 + 没有等待任务 + 没有正在执行的任务**。

这是模拟类问题里判断“系统已无事可做”的标准**静止判定（quiescence detection）**。少了任何一条都会提前结束或死循环。

关闭后不是立即退出，而是继续“空转”处理剩余队列和占用中的跑道——这体现了**关闭 ≠ 立即停止**，只是停止接受新请求。

***

## 四、复杂度与适用性

* **时间复杂度**：`O(T × R)`，T 为模拟总时间，R 为跑道数。每时刻扫描跑道两次（释放 + 调度），队列操作为 O(1)。
* **空间复杂度**：`O(R + N)`，N 为同时等待的飞机数。

时间驱动模拟的代价是“空闲分钟也要空转”，但题目中每分钟都可能有人工输入，且 T 由输入自然终止，这个代价是题目本身决定的，无法避免。相比之下，事件驱动模拟虽然能跳过空闲时间，但会因为“每分钟都要读输入”而失去优势，反而增加实现复杂度。

***

## 五、一句话总结

> **用“结束时刻数组”表示跑道状态、用“双 FIFO 队列”表示两类待办任务，以固定四步（释放→到达→调度→判定）推进离散时间，靠“先取降落队列”实现降落的全局优先级，在任务分配瞬间结算等待时间，在系统静止时结束模拟并输出聚合统计。**

这是一种典型的**资源受限的任务调度模拟**范式：状态用最简容器表达，规则用“取队顺序”表达，统计用增量累加表达。
