## 1. 三种复习模式，别混着做

每天的复习只做**其中一种**，混着做往往什么都没做成。

### 模式 A：精读（针对 12 份完整档）——30~40 分钟

适用：本题已有 §1 第一反应、§2 尝试轨迹、§3 题眼。

1. **读 §0 一句话题意 + §6 可迁移**（1 分钟）：知道这题在练什么。
2. **盖上档案和代码，自己重写**（15 分钟）：只允许看题面（`00NN.md` 的 §0 或原题链接）。
3. **对拍**（5 分钟）：`python 算法/tools/check.py --quiet` 过语法；再手造 2 组边界用例。
4. **读 §2 尝试轨迹 + §3 关键洞察**（5 分钟）：重点看"我当时错在哪"，不是看正确答案。
5. **在 §7 复习记录加一行**（2 分钟）：`日期 | 不看代码重写 | 通过/失败 | 卡在哪`。
6. 若失败：`下次复习` 改成明天，并在 `索引/错因.md` 对应标签下加一条。

> 12 份完整档（`完整度: 完整`）：`0015 0128 0189 0274 0436 0735 0790 1254 2897 3551 3644 3942`。其余 188 份是 `待补`，走模式 B。

### 模式 B：回填（针对 188 份待补档）——8~10 分钟/题

适用：档案只有 front-matter + 代码 + 待补清单。**这类题的目标不是重做，而是把"代码备份"变成"可复习的档案"。**

1. **只看标题**，先自己口述：输入是什么、要求什么、限制多大（1 分钟）。
2. 打开档案 §1 的代码，**读懂**（3 分钟）。读不懂就看 §3 外部题解。
3. 只填两件事（3 分钟）：
   - §0 一句话题意：一句自己的话，不抄题目。
   - §6 关键洞察：**这题的"题眼"是哪一句**（没有就写"没看出来"，这也是有效结论）。
4. 把 front-matter 的 `完整度: 待补` 改成 `完整`（或 `简版`）。
5. 填不出来就**保留待补**，别硬编——编了下次会被自己骗。

> 一次最多回填 3 题。回填 5 题就累了，质量会掉。

### 模式 C：抽考（针对模式卡）——10 分钟

适用：想检验"能不能迁移"，而不是"这道题会不会"。

1. 打开 `模式/` 里的一张卡，只看「识别信号」。
2. 说出：**看到什么信号 → 用哪个模板 → 有哪两个坑**。
3. 再看「例题」列，任选一题，盖住代码说出思路。
4. 说不出来 → 这张卡对应的例题要回去重做（回到模式 A）。

## 2. 节奏表

### 每日 30 分钟（工作日常规）

| 时间 | 动作 |
| --- | --- |
| 0–5 min | 打开 `索引/待复习.md`，确认今天到期的是哪几题 |
| 5–25 min | 模式 A（1 题精读）**或** 模式 B（2–3 题回填） |
| 25–30 min | 更新 §7 / `下次复习` / `错因` |

### 每周 90 分钟（周复盘）

- 30 min：把本周失败的题集中重做一次（`错因` 里本周新加的条目）。
- 30 min：模式 C 抽考 2 张卡。
- 30 min：若某个模式又碰到新题，回填该题的 §6 并更新模式卡「演化记录」。

### 每月 2 小时

- 更新 `索引/时间.md`、`索引/错因.md` 的"观察"段。
- 某错因 ≥ 3 条 → 写一条对策（写进 `错因.md` 末尾或对应模式卡）。
- 抽 3 题做"月度抽考"：**只看题名，讲思路 + 复杂度 + 一个反例**。

## 4. 复习时到底写什么（最小动作清单）

不要写长篇笔记，只写这些：

1. **一句话题意**（自己的话，10 个字左右）
2. **题眼**（"我想不到的那一句"，没有就写"没看出来"）
3. **一个反例**（这题最容易错的一组输入）
4. **§7 一行复习记录**（日期 | 方式 | 结果 | 卡在哪）

> 三条以上就过量了。`整理原则.md` §1.3：**只记真的，不补假的**。

## 5. "这题算会了"的三级标准

| 级别 | 标准 | 对应动作 |
| --- | --- | --- |
| L1 会写 | 不看代码能过编译 + 过自己造的 2 组用例 | `状态: 独立AC`，`下次复习` +14 天 |
| L2 会讲 | 能讲清题眼 + 复杂度 + 一个反例，不卡壳 | 复习记录写"口头讲通"，+30 天 |
| L3 会迁 | 新题里看到同类信号，能主动想到这个模式 | 更新对应 `模式/` 卡的「演化记录」 |

**只到 L1 不算会**——下次换个马甲就不认识了。

## 6. 卡住时的处置

| 症状 | 处置 |
| --- | --- |
| 代码编译不过 | `python 算法/tools/check.py --quiet`；OJ 片段靠 `算法/tools/oj.h`（C++）或 `ojc.h`（C）补头文件 |
| 读不懂某题的代码 | 看档案 §3 的外部题解（`灵神-*.cpp` 的头部有原文链接）；仍然不懂就先跳过，别耗 |
| 觉得"这题我做对了但说不清" | 直接记 `错因: [证明不出]`，这是最值钱的标签 |
| 发现档案/代码有错 | 别改代码，把 `状态` 改成 `待重做`，在档案里写清错在哪，并按 `整理原则.md` §8.5 走 |
| 一题耗超过 40 分钟 | 停，记下卡点，去看 §3，**当天必须收尾**，不要拖成三天 |
| 想整理而不是复习 | 关掉整理，去看 `索引/待复习.md`——整理不产出"会"，只产出"以后能复习" |

## 7. 五个常见误区

1. **刷数量代替复习**。200 题里只有 12 份完整档，剩下的如果不回填，就永远是"陌生代码"。
2. **只看外部题解**。灵神写得再好也不是你的；看完必须回到 §0/§6 用自己的话写一遍。
3. **一次开 20 题**。回填一次 3 题封顶，否则第二天全忘。
4. **把"整理"当学习**。整理是投资，复习是兑现；只投资不兑现等于没学。
5. **按标签随机刷**。先走第 3 节的十阶段路线，标签索引只用来"补漏"和"查题"。
