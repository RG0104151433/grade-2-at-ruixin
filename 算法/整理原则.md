# 整理原则（可复用）

> 这份文档记录**怎样整理算法题**，不是记录题目本身。
> 目标：任何一次整理（包括半年后重来一遍）都可以照着这份文档做，结论一致。
> 最近一次全面执行：2026-10-27（见 [`README.md`](README.md) 的「结构变更记录」）。

---

## 0. 一句话原则

> **代码只保存"我的实现"，档案只保存"我的思考"，模式卡片只保存"能迁移的结论"。三者分开，各自不越界。**

---

## 1. 三条底层原则

### 1.1 存储唯一，索引导航

一道题（一份档案 + 若干代码）**只在一个物理位置**：`题目/NNNN-标题/`。

"专题、错因、月份、复习状态"全部是**多标签**，用 `索引/` 下的四条索引去链接，**绝不用文件夹分类**。

> 理由：文件夹是排他的。一道题既是"二分"又是"计数排序"又属于"10 月"，用目录装必定要复制或漏标；用索引则零成本。
> 代价：需要维护 4 个薄索引文件（每行一句话，5 分钟能补完）。

### 1.2 档案记"思考"，代码记"实现"

| 内容 | 放哪 | 判断标准 |
| --- | --- | --- |
| 我第一反应是什么、卡在哪、被什么反例打脸 | 档案 §1/§2 | 半年后重看能想起"当时为什么这么想" |
| 关键洞察、正确性论证、复杂度、边界 | 档案 §3/§4 | 能讲给别人听的三句话 |
| 可复用的模板、识别信号、易错点 | `模式/` 卡片 | 下一题能直接用 |
| 解题代码 | `vN-*.cpp` | 只留一行"为什么这么写"的注释 |

**严禁**把大段内心独白写进代码注释——`3551` 的旧版就是这样，一合并就丢。这类内容必须搬进档案 §2。

### 1.3 只记真的，不补假的

过去做过但已经想不起来的题，**允许只写"题意 + 关键洞察 + 状态"的简版**，并在档案里写 `（当时未记录）`。

原因：编造出的"当时的想法"会污染判断——未来的你会以为"这个模式我早就会了"，从而跳过真正的薄弱点。

## 2. 目录与职责

```
算法/
├── README.md                # 入口：结构、统计、结构变更记录
├── 整理原则.md              # 本文件：怎么做整理（可复用）
├── 模板/
│   ├── 题目档案模板.md
│   └── 模式卡片模板.md
├── 题目/NNNN-标题/          # 唯一存储：一份档案 + 多版代码 + 可选附录
│   ├── NNNN.md
│   ├── v1-方法关键词.cpp
│   ├── v2-方法关键词.cpp
│   └── 附录-XXX.md          # 原始讨论稿/长文，原样保留
├── 模式/                    # 母题卡片（二阶知识，会长大）
├── 索引/
│   ├── 专题.md              # 按知识点（精读题）
│   ├── 专题-早期归档.md     # 按知识点的批量导航（待补档）
│   ├── 错因.md              # 按错误类型
│   ├── 待复习.md            # 按复习日期
│   └── 时间.md              # 按月份（保留原始时间线索）
├── 专题笔记/                # 跨题的长笔记（STL 精讲、早期题解分册等），只归档不改写
├── 竞赛备赛/                # 百度之星 / 码蹄杯资料，只归档不改写
└── tools/
    ├── oj.h / ojc.h         # OJ 片段缺的头文件 + using namespace std（C++ / C）
    ├── check.py             # 语法（C++→C 回退）/编码/命名/档案自检
    └── split_multi.py       # 拆分“一个文件多份实现”
```

职责边界：

- `题目/` 里**不放**跨题内容（模板、总结、比较表）。跨题的东西属于 `模式/` 或 `索引/`。
- `索引/` 里**不放**内容，只放链接 + 一行注解。注解超过 3 行就该升级成模式卡片。
- `模板/` 是"抄作业的地方"，永远保持与时俱进：改了规范先改模板。

## 3. 命名规范

| 对象 | 规则 | 例 |
| --- | --- | --- |
| 题目目录 | `NNNN-官方中文标题`，4 位补零 | `0274-H指数`、`0015-三数之和` |
| 档案 | 与目录同号：`NNNN.md` | `0274.md` |
| 代码（自有） | `vN-方法关键词.cpp`，N 从 1 开始，**按做题时间顺序** | `v1-排序二分.cpp`、`v2-计数-线性.cpp` |
| 代码（外部题解） | `灵神-小节名.cpp` / `官方-小节名.cpp` / `题解-小节名.cpp` | `灵神-写法二-小优化.cpp` |
| 原始材料 | `附录-XXX.md` / `附录-XXX.cpp` | `附录-DS引导记录.md`、`附录-多版本对照.cpp` |

外部题解的前缀按作者定：灵神 → `灵神-`，力扣官方账号 → `官方-`，其他作者 → `题解-`（作者名写在文件头）。
小节名取文章的 `###` 标题（清洗全角标点/LaTeX），无标题时用 `解法N`。

硬性禁止（会导致检索、编译脚本、GitHub 预览出问题）：

- 空格、全角括号 `（）`、全角逗号 `，`、感叹号 `！`、书名号
- 主观评价入名（旧例：`3727（没必要写什么了）.cpp` → 改为 `v1-绝对值重排贪心.cpp`，吐槽搬进档案）
- 作者名入名（旧例：`3551大肥鱼改的.cpp` → `v2-环置换计数.cpp`，出处写进档案）
- 无扩展名文件（旧例：6 个文件没有 `.cpp`，Windows 里显示成"文件"而不是"C++ source file"）

> `tools/check.py` 会自动检查名称里的空格/全角标点与扩展名。

## 4. 档案模板与字段理由

模板见 [`模板/题目档案模板.md`](模板/题目档案模板.md)。核心字段与存在理由：

| 字段 | 什么时候写 | 解决什么问题 |
| --- | --- | --- |
| front-matter `状态` | 每次做题/复盘 | 区分"自己做出来的"和"看答案的"，是复习优先级的唯一依据 |
| front-matter `错因` | 复盘时 | 8 个固定标签，可聚合出"我总栽在哪" |
| front-matter `下次复习` | 每次复盘 | 让复习变成可执行队列，不靠记性 |
| §1 第一反应 | **做题前 30 秒** | 唯一能对比"成长"的基准线；事后无法伪造 |
| §2 尝试轨迹 | 做题中/做完立刻 | 记录**反例**和**被打脸的那一步** |
| §3 关键洞察 | 做完 | 只写"我想不到的那一句"，不抄题解全文 |
| §4 正确性 + 复杂度 + 边界 | 做完 | 逼自己写三句话论证；边界清单是"边界漏"的唯一解药 |
| §5 版本对照 | 一题多解时 | 说清"为什么后来的更好"，否则多解只是仓库垃圾 |
| §6 可迁移 | 做完 | **没有 §6 的档案只是代码备份，不是学习资料** |
| §7 复习记录 | 复习后 | 让"学会了"可验证 |
| §8 关联 | 做完 | 制造横向连接，是模式卡片的原材料 |

### `状态` 枚举（固定，不要新增同义词）

`独立AC` / `提示后AC` / `看题解后AC` / `未AC` / `待复核` / `待重做`

- `待复核`：代码能过，但当时的状态/思路没记录，第一轮复习要确认"是不是真会"
- `待重做`：已知有错（编译不过、逻辑错）

### `错因` 标签（固定 8 个）

`读题错` / `边界漏` / `复杂度没达标` / `数据结构选错` / `证明不出` / `模板忘` / `实现bug` / `看题解太快`

新增标签要同时更新 `索引/错因.md` 的标签表，否则聚合会失效。

### 分级与成本控制（决定这套方法能不能长期活下去）

| 级别 | 触发条件 | 工作量 |
| --- | --- | --- |
| **完整档** | 首次遇到新模式 / 卡壳 > 20 分钟 / 做错 / 一题多解 / 复习失败 | 10~15 分钟 |
| **简版** | 其余所有情况（默认） | ≤ 3 分钟：front-matter + 一句话题意 + 一句话洞察 + 边界 + 复习一行 |
| **待补** | 过去做的题、没素材 | 1 分钟：front-matter + 题意，标 `完整度: 待补` |

> 现实提醒：**整理时间不能超过做题时间的一半**。如果发现自己在"美化笔记"，立刻降级为简版。

## 5. 外部题解收录规则（灵茶山艾府 / @endlesscheng）

### 5.1 收录门槛

- **必收**：所有 **困难** 题（不看通过率）。
- **按需收**：其余题里，力扣中国站**通过率 < 55%**（不限难度，用实时数据，不是印象）。

> 设计理由：困难题基本都要“看一篇好题解才可能学会”，所以一律收；其余题只捞“自己大概率一遍过不了”的（通过率是个粗糙但可用的代理指标）。
> 阈值和当时的通过率一起写进档案，以后调阈值时能看出“当时依据什么收的”。

**祖父条款**：第一批（17 题那批）是按更早的“中等及以上 且 通过率 < 60%”收的。按现阈值重新卡一遍，只有 `3644`（中等 55.7%）不符合；
它**不删**，但在档案的来源行标注“按第一批旧阈值收的”。其余七篇（`0015 0128 0189 0274 0735 0790 3942`）按现阈值仍然成立。

### 5.2 来源优先级

1. **灵茶山艾府**（@endlesscheng）——首选；
2. 他未写该题时，退而用**力扣官方题解**；官方也没（或无 C++）时用**题解区最高赞**。

补位的题在档案里写清作者与“不是灵神”，**不假装是灵神题解**。两种情况的已收录例子：
`028`（官方）、`962`（题解区 @Algo-Goer）、`726`（灵神只写了 Go，C++ 用官方）。

### 5.3 存放位置与格式

放在题目档案末尾的独立小节，**必须与“我的思路”物理隔开**：

```markdown
### 灵神：灵茶山艾府（@endlesscheng）

> 来源：[文章标题](URL)　👍 数字　抓取于 YYYY-MM-DD
> 版权归原作者；正文为原文代码前的摘录，代码已落盘为同目录 `.cpp`。

（原文代码块之前的正文，标题降两级）

**复杂度（原文）**
- 时间复杂度：……

| 代码文件 | 原文小节 |
| --- | --- |
| `灵神-写法一.cpp` | 写法一 |
```

规则：

- **正文**只取“第一个代码块之前”的部分；后续章节的推导段落不搬（太长且容易失真）。
- **代码**每段都落盘成一个 `.cpp`，文件头写：来源/URL/小节/“外部题解，非本人实现”/抓取日期。
- 同一篇有多个写法时**全部保留**（写法一、写法二、优化版……），文件名用小节名；
  这也满足“多解法/多优化要写明白”的要求。
- 非代码的代码块（只有文字说明的“举例”块）跳过——否则会往 `.cpp` 里写散文。
- 若某篇没 C++（比如灵神只写了 Go），明确写“该文没有可用的 C++ 代码，未提取”。

### 5.3b 找不到怎么办

若该题题解区确实没有他的文章：写明**核验方式与结论**，不要静默跳过。

> 例（`0436`）：“截至 2026-10-27，本题题解区没有 @endlesscheng 的文章。已完整翻检该题 655 篇题解（20 篇/页 × 33 页）确认。”
>
> 题量大时更快的做法：加 `orderBy: MOST_UPVOTE` 按热度翻前几页（他的文章很少跌出前 20）。

### 5.4 抓取与落盘（可复现）

力扣中国站的 GraphQL 端点（无需登录）：

```bash
# 题目列表（难度/通过率/标签），skip 分页，每次最多 100 条
curl -s https://leetcode.cn/graphql/ -H 'content-type: application/json' \
  -H 'Referer: https://leetcode.cn/problemset/' \
  --data-binary '{"query":"query problemsetQuestionList($categorySlug: String, $limit: Int, $skip: Int, $filters: QuestionListFilterInput) {problemsetQuestionList(categorySlug: $categorySlug, limit: $limit, skip: $skip, filters: $filters) {total questions {frontendQuestionId titleSlug titleCn difficulty acRate topicTags {nameTranslated}}}}","variables":{"skip":0,"limit":100,"filters":{}}}'

# 某题的全部题解（找作者 username = endlesscheng）
#   questionSolutionArticles(questionSlug:$slug, skip:$skip, first:20) -> edges.node.author.username

# 拿到 article slug 后取正文
#   solutionArticle(slug:$slug) -> {title content author{username}}
```

注意：

- `first` 上限 20，`skip` 按 20 递增（用 100 会返回"翻页参数错误"）。
- 通过率是**实时值**，会变；档案里记录抓取日期。
- 正文是 Markdown（带 `$\textit{nums}$` 之类 LaTeX），引用时可以保留但不必逐字转写。

## 6. 索引与复习闭环

### 6.1 五条索引

| 索引 | 维护动作 | 更新时机 |
| --- | --- | --- |
| `专题.md` | 每种专题一张小表：题号 + "这题对这个专题贡献了什么" | 每加 1 题 |
| `错因.md` | 8 个标签聚合 + 观察 + 对策 | 每次复盘失败 |
| `待复习.md` | 按 `下次复习` 分组 | 每次复盘后排日期 |
| `时间.md` | 月份 → 题号 + 一句话 + 状态 | 每月初补上个月 |
| `专题-早期归档.md` | 按力扣官方标签分组，只放题号链接 | 批量导入后生成一次，之后手动补 |

### 6.2 复习节奏（三遍法）

| 时机 | 做法 | 通过标准 |
| --- | --- | --- |
| 当天 | 写 §1（做题前）→ 做题 → 写 §2~§4 | 档案完整 |
| 次日 | 不看代码**重写**一遍 | 能独立过编译 + 过 2 组手造用例 |
| 一周 | 只看题名，**口头讲**思路 + 复杂度 + 一个反例 | 讲得顺，不卡壳 |
| 一月 | 从 `待复习.md` 抽考 | 同上 |

失败处理：`下次复习` 改成次日，§7 记录"卡在哪"，`错因` 加标签。

### 6.3 日期规则

| 状态 | 下次复习 |
| --- | --- |
| 待重做 / 未AC | +1 天 |
| 看题解后AC / 提示后AC | +3 天 |
| 待复核 | +7 天（第一轮集中复核） |
| 独立AC | +14 天 |
| 复习通过 2 次 | +30 天，之后不再进队列 |

## 7. 模式卡片

### 7.1 创建门槛

**同一模式出现 ≥ 2 题**才建卡；只有 1 题先挂在 `索引/专题.md` 的「待沉淀」表里。

理由：只有 1 个例子时，还分不清"这是通用模式"还是"这题的特殊技巧"，过早建卡会造出一堆永远不长的空壳。

### 7.2 卡片结构

`一句话` → `识别信号` → `模板代码` → `例题（题号 + 这题贡献了什么）` → `我的易错点` → `演化记录`

- `识别信号` 是卡片最有价值的部分：它是"从题面到模式"的触发器，要写**看得见的东西**（题目要求、数据范围、关键词），不要写"需要二分"这种结论。
- `演化记录` 每次更新都加一行，能看出这个模式是怎么被自己一点点补全的。
- 卡片的例题必须**链接回档案**，不要复制代码。

### 7.3 什么时候该拆卡

如果一张卡里出现了"两种完全不同的模板代码"，说明门槛判断错了，拆成两张。

## 8. 工程约定

1. **编码统一 UTF-8（无 BOM）**。历史上有 8 个文件是 GB18030（中文注释在 GitHub/Linux 下全是乱码），已全部转换。
   判断方法：`python -c "open('x.cpp',encoding='utf-8').read()"`，报 `UnicodeDecodeError` 就是非 UTF-8。
2. **行尾交给 Git 统一**：仓库开启了 `core.autocrlf=true`（库内 LF、检出到 Windows 为 CRLF），不要手工转行尾，也不提交 `.gitattributes` 里的 `eol` 规则——两者混用会造成全仓 diff。
3. **编译自检**：OJ 片段只有 `class Solution`，用统一头文件补全：

   ```bash
   python 算法/tools/check.py           # 全量：语法 + 编码 + 命名 + 档案完整性
   python 算法/tools/check.py --quiet    # 只打问题
   g++ -std=c++23 -fsyntax-only -include 算法/tools/oj.h 算法/题目/0274-H指数/v2-计数-线性.cpp
   ```

   三条豁免规则（否则一跑就是一片红）：
   - C++ 失败后再用 `gcc -x c -std=c17 -include tools/ojc.h` 试一次：早期用 C 写的那些（`malloc` 不转指针）本来就不是 C++；
   - `附录-*.cpp` 不参与编译（本来就是“一个文件多份实现”的原件）；
   - 档案 `状态: 待重做` 的题只提示不回错。
4. **移动/改名一律用 `git mv`**，保住文件历史。
5. **不改旧代码**：发现代码有问题（编译不过、逻辑错）**也不当场改写**，而是
   - 在档案里标 `状态: 待重做`
   - 在 §2/§4 写清错在哪
   - 等复习那一轮再写 `v2`（新文件），旧文件保留

   理由：旧文件是"当时水平的证据"，改掉就失去了对比价值；而且"整理"和"重做"混在一起会让 diff 变得无法审阅。
6. **一题多解不新建目录**：所有版本放同一题目目录，靠 `vN` 前缀排序，档案 §5 写对照表。
7. **原始材料只归档不改写**：与 AI 的长对话（如 `附录-DS引导记录.md`）原样保留，结论必须自己重写进档案。它是证据，不是笔记。
8. **题号不能只信文件名**：早期文件里的题号会错（`2的幂.cpp` 其实是 231、`235之积.cpp` 是 263、`875时间内吃香蕉` 其实是 1011……）。
   正确的校对方式：拿力扣的 `codeSnippets`（C++ 函数签名）去比文件里是否真有那个函数名，对不上就另找题号。
   2026-10-27 批量导入时，189 个文件里有 13 个是这种情况。
9. **多份实现同文件 → 拆**：早期文件常把“错解/正解”或几版写法压在一个文件里（`redefinition` 报错）。
   `tools/split_multi.py --apply` 会按顶层定义边界拆成 `v1/v2/…`，并且**每段都能单独编译才拆**；
   拆不动的（含真错解、依赖互相引用）改名为 `附录-多版本对照.cpp` 归档，并在档案里写清原因。

## 9. 本次迁移的完整流程（可复现）

按顺序执行，每步都能单独停下：

1. **补格式**：无扩展名文件 `git mv` 加 `.cpp`；顺手改正明显笔误（`1689-哈希表解法` 的内容是 1679，已改）。
2. **转编码**：`gb18030 → utf-8`（读字节 → decode → encode → 写回），保留 CRLF；转完复查"是否还有非 UTF-8"。
3. **建骨架**：`git mv` 顶层目录；建 `题目/ 模式/ 索引/ 模板/ tools/`。
4. **搬文件**：`git mv` 到 `题目/NNNN-标题/vN-方法.cpp`，方法名用"做法"而不是"作者/吐槽"。
5. **写档案**：先写有素材的（6~7 题完整档），其余简版；没素材的地方标 `（当时未记录）`。
6. **抓外部题解**：按 §5 的门槛判定 → 拉取 → 写进档案末尾的独立小节。
7. **建索引**：专题/错因/待复习/时间，各 20 行以内。
8. **提炼模式**：只建有 ≥ 2 例题的卡片（截至 2026-10-27 共 12 张），其余进「待沉淀」。
9. **同步外部文档**：仓库根 `README.md`、`文件地图.md` 的路径与统计；本目录 `README.md` 记录结构变更日期。
10. **自检**：`python 算法/tools/check.py` 全绿。

## 10. 反模式（比规范更重要）

1. **把整理当主业**。整理时间 > 做题时间的 50%，就一定做不长久。降级成简版。
2. **抄题解当档案**。把灵神/官方题解整段复制进 §3，等于没写。§3 只写"我想不到的那一句"。
3. **事后编造思考**。见 1.3。
4. **全仓大迁移**。把 `力扣等编程（未整理）/` 的 189 个早期文件逐个建档 = 纯体力活、零收益。只捞"错题 / 一题多解 / 模板题"。
5. **为了整齐而改代码**。整理只管"位置和命名"，不管"正确性"。代码问题只标状态（见 8.5）。
6. **索引写成长文**。索引超过 3 行注解说明该升级成模式卡片了。
7. **模式卡片抢先建**。1 个例题就建卡，最后会有一堆"写了模板但从不复习"的僵尸卡片。
8. **删除旧目录**。旧目录（旧月份、旧命名）在 Git 历史里就够了，但**不要在工作区留着两套**；迁移完成后旧目录必须清掉，否则两边会各自长出内容。
