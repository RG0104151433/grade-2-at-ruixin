# 模式：二分答案

## 一句话

题目问"最小的最大 / 最大的最小 / 最少的时间"，而**答案本身**具有单调性时，直接对答案二分，再用一个 `check(答案)` 判断可行性。

## 识别信号

- 问的是"**最小**的能满足条件的 X"或"**最大**的能达到的 X"
- X 是某个**数量/时间/容量/速度/阈值**，而不是数组里的下标
- 给定 X 后，能在 O(n) 或 O(n log n) 内**判断"能不能做到"**（贪心/模拟）
- 数据范围形如 `n ≤ 10⁵`，答案范围到 10⁹ 或 10¹⁴ → `log` 层二分

## 模板

```cpp
// 求最小的可行 X：check(X) 单调（X 越大越容易满足）
long long lo = 下界, hi = 上界;          // 上界要自己算，注意 long long
while (lo < hi) {
    long long mid = lo + (hi - lo) / 2;
    if (check(mid)) hi = mid;            // mid 可行 → 答案 ≤ mid
    else lo = mid + 1;
}
return lo;                                // 二分结束时 lo 就是最小可行值
```

三步走：**① 单调性论证（为什么 X 越大越容易）② 写 check（能不能在时限内做完）③ 定上下界（最容易错）**。

## 我的易错点

- **上界取小**了：`2187` 的上界是 `min(t) * totalTrips`，`3296` 的上界要按二次式估，取小会漏掉正确答案
- check 用 `int` 累加溢出（`Σ mid/t[i]` 可以到 10¹⁴）
- `while (lo < hi)` 配 `hi = mid` 时，`check` 必须对"可行"返回 true；写反了会死循环
- 单调性没论证就直接二分——有些题的"可行性"并不是单调的，那就不是二分答案
- 二分出来的值要**再验一次**（尤其是 `n` 很小或边界不可达时）
