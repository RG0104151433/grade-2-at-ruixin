# 模式：二分答案

## 一句话

题目问"最小的最大 / 最大的最小 / 最少的时间"，而**答案本身**具有单调性时，直接对答案二分，再用一个 `check(答案)` 判断可行性。

## 识别信号

- 问的是"**最小**的能满足条件的 X"或"**最大**的能达到的 X"
- X 是某个**数量/时间/容量/速度/阈值**，而不是数组里的下标
- 给定 X 后，能在 O(n) 或 O(n log n) 内**判断"能不能做到"**（贪心/模拟）
- 数据范围形如 `n ≤ 10⁵`，答案范围到 10⁹ 或 10¹⁴ → `log` 层二分

## 模板

> 【计挑赛补充 2026-11-21】最值措辞只是线索。先把题目改写为可行性判定，再证明单调性；本页末尾用 1011 展示完整读题过程。

```cpp
// 求最小的可行 X：check(X) 单调（X 越大越容易满足）
long long lo = 下界, hi = 上界;          // 上界要自己算，注意 long long
while (lo < hi) {
    long long mid = lo + (hi - lo) / 2;
    if (check(mid)) hi = mid;            // mid 可行 → 答案 ≤ mid
    else lo = mid + 1;
}
return lo;                                // 二分结束时 lo 就是最小可行值
```

三步走：**① 单调性论证（为什么 X 越大越容易）② 写 check（能不能在时限内做完）③ 定上下界（最容易错）**。

## 我的易错点

- **上界取小**了：`2187` 的上界是 `min(t) * totalTrips`，`3296` 的上界要按二次式估，取小会漏掉正确答案
- check 用 `int` 累加溢出（`Σ mid/t[i]` 可以到 10¹⁴）
- `while (lo < hi)` 配 `hi = mid` 时，`check` 必须对"可行"返回 true；写反了会死循环
- 单调性没论证就直接二分——有些题的"可行性"并不是单调的，那就不是二分答案
- 二分出来的值要**再验一次**（尤其是 `n` 很小或边界不可达时）

## 【计挑赛补充 2026-11-21】从优化目标建立判定模型

1011 中“按原顺序”“D 天内”“最小载重”分别决定：不能排序；允许少于 D 天；二分的是容量 C。改写为 `check(C) = 按原顺序装船时，所需天数是否 ≤D`。

**check 的理由：**当前这天能继续装就继续装，不能装才换天。对固定容量，尽量长的合法前缀不会比提前结束更晚推进到后续货物，因此能得到最少所需天数。容量增大可沿用旧分组，所以“可行”不会变回“不可行”。

关键代码：`days=1, load=0`；若 `load+w>C`，先 `++days, load=0`，再装当前物品。若采用的下界不保证 `C>=maxWeight`，必须另外拒绝单件超载。

上下界为最大单件重量与重量总和（假设非空、重量为正、D≥1）；总和可行，最大单件只是下界，不保证可行。上文循环求最小可行值，不能找到一个可行 mid 就立即返回。

**复杂度提醒：**若范围宽度为 U、check 为 O(n)，总时间 O(n log(U+1))，还包括读入等预处理；不是 O(n+log U)。复习时先算一次 check 的成本，再乘二分轮数。这对应你 11 月 8 日报告第 14 题。

条件改变要重新建模：若允许重排、必须恰好若干组、允许拆分物品，原 check 的解释不能不加分析地沿用。
