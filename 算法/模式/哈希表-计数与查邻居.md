# 模式：哈希表——计数与查邻居

## 一句话

需要 **O(1) 判断"某个值在不在 / 出现了几次"** 时用哈希表，把"扫描一遍数组找它"的 O(n) 查询变成 O(1)。

## 识别信号

- 题目要"是否存在"、"配对"、"去重"、"最长连续段"
- 值域很大（10⁹）不能开数组计数
- 朴素解法里出现"对每个元素再扫一遍数组"
- 题目要求 O(n)，且显然要"记住已经见过的东西"

## 两种用法（别混）

**A. 查邻居（存在性）**——最长连续序列

```cpp
unordered_set<int> st(nums.begin(), nums.end());
for (int x : st) {              // 注意：遍历集合，不是遍历 nums
    if (st.contains(x - 1)) continue;  // 有前驱 → x 不是起点，跳过
    int y = x + 1;
    while (st.contains(y)) y++;
    ans = max(ans, y - x);
}
```

**B. 配对消去（计数）**——K 和数对

```cpp
unordered_map<int,int> cnt;
for (int x : nums) {
    if (cnt[target - x]) { cnt[target - x]--; ans++; }  // 有对手就配
    else cnt[x]++;                                      // 没有就先登记
}
```

## 我的易错点

- `0128` 的经典坑：遍历 `nums` 而不是 `st`。若 `nums = [1,1,1,...,2,3,4,5]`，每个 `1` 都会跑一遍内层循环 → O(n²) 超时
- 配对题：先查对手、再登记自己，顺序不能反（反了会自己配自己）
- `cnt[x]` 这种写法会**插入**不存在的键；只想读时用 `find` / `contains`
- `unordered_map` 的 `operator[]` 在 `key` 是 `int` 时没问题，但 `map` vs `unordered_map` 的复杂度差别要看题（见 `../专题笔记/map_unordered_map精讲.md`）
