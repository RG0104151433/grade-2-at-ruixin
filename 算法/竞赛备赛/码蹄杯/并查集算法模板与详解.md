## 1. 并查集是什么

### 一句话理解

并查集是一种**树形结构**，用来高效处理两类操作：

- **合并（Union）**：把两个元素所在的集合合并成一个
- **查询（Find）**：判断两个元素是否在同一个集合

### 核心思想

```
每个集合用一棵树表示，树根是这个集合的"代表元"
```

```
原始状态：        合并 1 和 3 后：
  0   1   2   3       0   1→3   2   3
  ↑   ↑   ↑   ↑       ↑
 根  根  根  根       根
```

`find(x)` 返回 x 所在树的根节点。如果两个元素的根相同，就在同一集合。

### 复杂度

经过路径压缩优化后，单次操作**近似 O(1)**（严格来说是反阿克曼函数，竞赛中视为常数）。

## 2. 基础模板（路径压缩）

### 模板代码

```cpp
const int N = 100010;  // 根据数据范围开，通常比最大 n 大 5-10

int fa[N];             // fa[x] = x 的父节点

// ① 初始化：每人都是自己的爹
void init(int n) {
    for (int i = 1; i <= n; i++) fa[i] = i;
}

// ② 找根：递归找 x 的祖先
int find(int x) {
    return x == fa[x] ? x : fa[x] = find(fa[x]);
}

// ③ 合并：把 i 所在集合合并到 j 所在集合
void merge(int i, int j) {
    int x = find(i), y = find(j);
    if (x != y) fa[x] = y;
}
```

### 逐行逻辑详解

| 代码 | 在干什么 |
|------|---------|
| `int fa[N]` | 父节点数组，`fa[x]` 存的是 x 的"上级"，不是根 |
| `init(n)` | 一开始每个人都是独立的，所以自己的上级就是自己 |
| `find(x)` | 递归找 x 的根——如果 fa[x]==x，说明 x 就是根；否则顺着 fa[x] 往上找 |
| `fa[x] = find(fa[x])` | **路径压缩**：找到根之后，直接把 x 的父节点改成根，下次找就快了 |
| `merge(i, j)` | 先找 i 和 j 的根，如果根不同，把其中一个根的父节点指向另一个根 |
| `if (x != y)` | 只有根不同才合并，相同说明已经在同一集合，不用操作 |

### 路径压缩的原理

没路径压缩时，找根的路径可能是这样的：

```
1 → 2 → 3 → 4 → 5（根）
```

每次 find(1) 都要走 4 步。路径压缩后，第一次 find(1) 就把 1 直接挂到 5 下面：

```
1 → 5（根）
2 → 5
3 → 5
4 → 5
```

下次再找任何节点，都是一步到位。

### 画图推演

```
init(5):
  fa[1]=1  fa[2]=2  fa[3]=3  fa[4]=4  fa[5]=5
  ①       ②       ③       ④       ⑤

merge(1, 3):
  find(1)=1, find(3)=3 → 不同 → fa[1]=3
  ①→③     ②       ③       ④       ⑤

merge(2, 4):
  find(2)=2, find(4)=4 → 不同 → fa[2]=4
  ①→③     ②→④     ③       ④       ⑤

find(1):  fa[1]=3, fa[3]=3 → 根=3，路径压缩后 fa[1]=3
find(2):  fa[2]=4, fa[4]=4 → 根=4，路径压缩后 fa[2]=4

merge(3, 5):
  find(3)=3, find(5)=5 → 不同 → fa[3]=5
  ①→③→⑤   ②→④     ③→⑤     ④       ⑤

merge(1, 2):
  find(1): fa[1]=3, fa[3]=5, fa[5]=5 → 根=5，路径压缩 fa[1]=5
  find(2): fa[2]=4, fa[4]=4 → 根=4
  根不同 → fa[5]=4
  ①→⑤→④   ②→④     ③→⑤→④   ④       ⑤→④
```

### 时间复杂度

- 单次 `find`：**近乎 O(1)**（反阿克曼函数，n=10^5 时不超过 5）
- 单次 `merge`：两次 find + 一次赋值，同 O(1)
- 总复杂度：O(m α(n))，m 是操作次数，α(n) ≤ 5

- **547·省份数量**：模板题，统计连通分量数
- **684·冗余连接**：合并时发现根相同 = 成环
- **1319·连通网络的操作次数**：统计连通分量数 - 1

## 3. 按秩合并（优化）

### 为什么需要按秩合并

路径压缩已经让 find 很快了，但极端情况下合并顺序可能导致树太高：

```
merge(1,2), merge(1,3), merge(1,4), merge(1,5) ...
     ①→②→③→④→⑤  （链状，每次合并都把大树挂到小树上）
```

### 模板代码

```cpp
int fa[N], rk[N];  // rk[x] = 以 x 为根的树的高度（近似）

void init(int n) {
    for (int i = 1; i <= n; i++) {
        fa[i] = i;
        rk[i] = 1;  // 每棵树初始高度为 1
    }
}

int find(int x) {
    return x == fa[x] ? x : fa[x] = find(fa[x]);  // 路径压缩照常
}

void merge(int i, int j) {
    int x = find(i), y = find(j);
    if (x == y) return;
    // 矮的挂到高的下面
    if (rk[x] < rk[y]) fa[x] = y;
    else if (rk[x] > rk[y]) fa[y] = x;
    else {               // 高度相等，随便挂一个，高度 +1
        fa[y] = x;
        rk[x]++;
    }
}
```

### 逻辑详解

| 代码 | 在干什么 |
|------|---------|
| `rk[x]` | 记录以 x 为根的树的"大致高度" |
| `rk[x] < rk[y]` | 把矮树的根挂到高树的根下面，树的高度不变 |
| 高度相等时 | 无论怎么挂，新树高度都会 +1 |

### 效果对比

```
不按秩合并：            按秩合并：
  ①→②→③→④→⑤         ①→②→③→⑤
                      ④→⑤
  find(5) 要走 4 步    find(5) 走 2 步
```

### 路径压缩 vs 按秩合并

| | 路径压缩 | 按秩合并 | 两者都用 |
|--|---------|---------|---------|
| 原理 | 找根时把节点直接挂到根 | 合并时矮树挂高树 | 各自优化不同环节 |
| 效果 | 让树变矮（扁平化） | 防止树长高 | 理论最优 |
| 实现 | 在 find 里做 | 在 merge 里做 | 各写各的 |
| 竞赛推荐 | **必用** | 可用可不用 | 追求极致性能时用 |

**竞赛建议：** 只写路径压缩就够了，99% 的题不会卡这个。按秩合并知道原理即可，码蹄杯不考这个细节。

### 例：统计连通分量数

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 100010;
int fa[N];

void init(int n) {
    for (int i = 1; i <= n; i++) fa[i] = i;
}

int find(int x) {
    return x == fa[x] ? x : fa[x] = find(fa[x]);
}

void merge(int i, int j) {
    int x = find(i), y = find(j);
    if (x != y) fa[x] = y;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;          // n 个节点，m 条边
    init(n);

    while (m--) {
        int u, v;
        cin >> u >> v;
        merge(u, v);
    }

    // 统计连通分量数
    int cnt = 0;
    for (int i = 1; i <= n; i++) {
        if (fa[i] == i) cnt++;  // 根节点个数 = 连通分量数
    }
    // 注意：路径压缩后 fa[i] 不一定等于 find(i)，
    // 但这里我们要的是"根节点"，所以用 fa[i] == i 判断
    // 更稳妥的做法：for (int i=1; i<=n; i++) if (find(i) == i) cnt++;
```

## 5. 种类并查集（扩展域）

### 解决什么问题

元素之间有"关系"（朋友/敌人、相同/不同），但关系不止一种，而且关系可传递。

**典型场景：**
- 朋友的朋友是朋友
- 敌人的敌人是朋友
- 等式 `a==b` 和 `a!=b` 同时存在，判断是否矛盾

### 核心思想

把每个元素拆成多个"域"，每个域代表一种状态。

**以 990·等式方程为例：** 有 26 个小写字母，要判断 `a==b` 和 `a!=b` 是否矛盾。

```
拆成两个域：
  x      → 表示"x 本身"
  x + 26 → 表示"x 的对立面"

a==b: 合并 (a, b) 和 (a+26, b+26)  → 相同阵营的在一起
a!=b: 合并 (a, b+26) 和 (a+26, b)  → 不同阵营的连起来
```

### 模板代码

```cpp
const int N = 200010;  // 开两倍大小
int fa[N];

void init(int n) {
    for (int i = 1; i <= n * 2; i++) fa[i] = i;  // 注意是 2n
}

int find(int x) {
    return x == fa[x] ? x : fa[x] = find(fa[x]);
}

void merge(int i, int j) {
    int x = find(i), y = find(j);
    if (x != y) fa[x] = y;
}

// 判断两个元素是否在同一集合
bool same(int i, int j) {
    return find(i) == find(j);
}
```

### 应用的两种模式

**模式①：只有两种关系（如 886 二分图）**

把 n 个人分成两组，某些人不能在同一组：

```cpp
// 人 i 的"矛盾域"是 i + n
// i 和 j 不能在同一组：
merge(i, j + n);
merge(i + n, j);

// 最后检查：如果 find(i) == find(i + n)，说明矛盾
```

**模式②：等式 + 不等式（如 990）**

```cpp
// 先处理所有等式
for (auto& eq : equations) {
    if (eq[1] == '=') {
        merge(eq[0] - 'a', eq[3] - 'a');
        merge(eq[0] - 'a' + 26, eq[3] - 'a' + 26);
    }
}

// 再检查所有不等式
for (auto& eq : equations) {
    if (eq[1] == '!') {
        if (same(eq[0] - 'a', eq[3] - 'a')) {
            cout << "false" << endl;
            return;
        }
    }
}
```

### 种类并查集 vs 普通并查集

| | 普通并查集 | 种类并查集 |
|--|----------|----------|
| 数组大小 | n | n × 种类数 |
| 关系 | 仅在"是否同一集合" | 还有"对立""不同"等关系 |
| 合并逻辑 | 直接合并 | 按关系规则跨域合并 |
| 判定 | 根相同 = 同一集合 | 根相同 = 同一状态域 |

### 练手题

- **990·等式方程的可满足性**：标准模板，先合并不等式再检查等式
- **886·可能的二分法**：扩展域二分图判定

## 6. 带权并查集（选学）

### 解决什么问题

不仅要知道元素是否在同一个集合，还要知道元素之间的**差值/比例关系**。

**典型场景：** `a / b = 2.0, b / c = 3.0`，求 `a / c`。

### 核心思想

在普通并查集的基础上，每个节点额外存一个权值 `dis[x]`，表示 x 到其父节点的"距离"或"比值"。

```cpp
double dis[N];  // dis[x] = x 到 fa[x] 的比值（x / fa[x]）
```

### 模板代码

```cpp
const int N = 100010;
int fa[N];
double dis[N];  // 权值：x 到 fa[x] 的比值

void init(int n) {
    for (int i = 1; i <= n; i++) {
        fa[i] = i;
        dis[i] = 1.0;  // 自己到自己的比值是 1
    }
}

int find(int x) {
    if (x == fa[x]) return x;
    int root = find(fa[x]);      // 先递归找根
    dis[x] *= dis[fa[x]];        // 路径压缩：更新 x 到新父节点的权值
    return fa[x] = root;
}

// 合并：已知 a / b = val
void merge(int a, int b, double val) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    // 把 ra 挂到 rb 下面，算出 dis[ra]
    // 公式推导：a / b = val
    // a / ra * ra / rb = a / b * b / rb = val * dis[b]
    // dis[a] * dis[ra] = val * dis[b]
    // dis[ra] = val * dis[b] / dis[a]
    fa[ra] = rb;
    dis[ra] = val * dis[b] / dis[a];
}

// 查询比值：a / b
double query(int a, int b) {
    if (find(a) != find(b)) return -1;  // 不在同一集合，无法确定
    return dis[a] / dis[b];  // a / b = (a/root) / (b/root)
}
```

### 带权 vs 普通

| | 普通并查集 | 带权并查集 |
|--|----------|----------|
| 存什么 | 父节点编号 | 父节点编号 + 到父节点的权值 |
| 路径压缩 | 只改父节点 | 父节点 + 权值一起更新 |
| 合并 | 直接挂 | 要算权值 |
| 适用场景 | 连通性判断 | 比例/差值关系 |

### 练手题

- **399·除法求值**：标准带权并查集模板题

## 7. 并查集在 Kruskal 中的应用

### Kruskal 全流程

```cpp
struct Edge {
    int u, v, w;
    bool operator<(const Edge& other) const {
        return w < other.w;
    }
};

vector<Edge> edges;
// ... 读入所有边 ...

sort(edges.begin(), edges.end());  // ① 按权值排序

init(n);  // ② 并查集初始化

int ans = 0, cnt = 0;
for (auto& e : edges) {
    if (find(e.u) != find(e.v)) {  // ③ 不会成环
        merge(e.u, e.v);
        ans += e.w;
        if (++cnt == n - 1) break;  // ④ 选够 n-1 条边
    }
}
```

### 并查集在其中的角色

| 步骤 | 并查集的作用 |
|------|------------|
| 排序后逐条选边 | 贪心选最小边 |
| `find(u) != find(v)` | 判断 u 和 v 是否已连通——如果已连通，再加边会成环 |
| `merge(u, v)` | 把两个连通分量合并 |
| `cnt == n-1` | 树有 n-1 条边，选够了就停 |

### 练手题

- **1584·连接所有点的最小费用**：Kruskal 的完整实现

## 8. 常见坑与调试指南

### 坑①：忘记调用 init()

```cpp
// 错误
int fa[N];
// 没有 init(n)，fa[i] 默认是 0，不是 i
// find(1) 会无限递归或返回 0

// 正确
init(n);
```

**检查清单：** 每次用到并查集，第一件事就是 `init(n)`。

### 坑②：merge 里比较的是 fa[u] 和 fa[v]，不是根

```cpp
// 错误
void merge(int i, int j) {
    if (fa[i] != fa[j]) {   // 比较的是直接父节点，不是根
        fa[i] = j;
    }
}

// 正确
void merge(int i, int j) {
    int x = find(i), y = find(j);  // 先找到根
    if (x != y) fa[x] = y;
}
```

**记住：** 永远用 `find()` 拿到根之后再做比较和操作。

### 坑③：大量递归导致栈溢出

递归版 `find` 在 n=10^5 且树很深时可能栈溢出。**保险写法：**

```cpp
// 非递归版 find（不会栈溢出）
int find(int x) {
    int root = x;
    while (fa[root] != root) root = fa[root];  // 先找根

    // 路径压缩：把路径上的所有节点直接挂到根
    while (x != root) {
        int next = fa[x];
        fa[x] = root;
        x = next;
    }
    return root;
}
```

**竞赛建议：** 递归版在 10^5 级别通常没问题，但如果你用递归版 + 大数据量 + 没有路径压缩，确实可能爆栈。非递归版作为备选方案。

### 坑④：用 fa[x] == fa[y] 判断连通性

```cpp
// 错误
if (fa[a] == fa[b]) // fa[a] 存的是父节点，不是根，路径压缩后也不一定是根

// 正确
if (find(a) == find(b))
```

**记住：** 判断连通性**一定**用 `find()`，不要直接读 `fa[]`。

### 坑⑤：多组测试数据忘记重置

```cpp
int T;
cin >> T;
while (T--) {
    int n, m;
    cin >> n >> m;
    init(n);  // 每组数据都要重新初始化！
    // ...
}
```

### 调试技巧

```cpp
// 打印当前并查集状态（用于调试）
void debug(int n) {
    cout << "idx: ";
    for (int i = 1; i <= n; i++) cout << i << " ";
    cout << "\nfa:  ";
    for (int i = 1; i <= n; i++) cout << fa[i] << " ";
    cout << endl;
}

// 统计连通分量数
int countSets(int n) {
    int cnt = 0;
    for (int i = 1; i <= n; i++)
        if (find(i) == i) cnt++;  // 注意用 find(i) 不是 fa[i]
    return cnt;
}
```

## 9. 并查集 + 哈希映射

### 解决什么问题

并查集要求节点编号是 0~n-1 或 1~n 的连续整数。但实际题目中，节点可能是**字符串**（邮箱、用户名）、**不连续的数字**（如 100, 200, 300）。

### 技巧：用 map 做映射

```cpp
unordered_map<string, int> id;  // 字符串 → 编号
int idx = 0;

int getId(string& s) {
    if (id.count(s)) return id[s];
    return id[s] = idx++;  // 分配新编号
}
```

### 完整示例：721·账户合并

```cpp
class Solution {
public:
    vector<vector<string>> accountsMerge(vector<vector<string>>& accounts) {
        unordered_map<string, int> emailToId;
        unordered_map<string, string> emailToName;
        int idx = 0;

        // 第一步：给每个邮箱分配编号
        for (auto& acc : accounts) {
            string name = acc[0];
            for (int i = 1; i < acc.size(); i++) {
                string& email = acc[i];
                if (!emailToId.count(email)) {
                    emailToId[email] = idx++;
                    emailToName[email] = name;
                }
            }
        }

        // 第二步：并查集
        int n = idx;
        vector<int> fa(n);
        iota(fa.begin(), fa.end(), 0);
        function<int(int)> find = [&](int x) {
            return x == fa[x] ? x : fa[x] = find(fa[x]);
        };
        auto merge = [&](int i, int j) {
            int x = find(i), y = find(j);
            if (x != y) fa[x] = y;
        };

        // 同一账户下的邮箱合并
        for (auto& acc : accounts) {
            int firstId = emailToId[acc[1]];
            for (int i = 2; i < acc.size(); i++) {
                merge(firstId, emailToId[acc[i]]);
            }
        }

        // 第三步：按根分组输出
        unordered_map<int, vector<string>> groups;
        for (auto& [email, id] : emailToId) {
            groups[find(id)].push_back(email);
        }

        vector<vector<string>> res;
        for (auto& [root, emails] : groups) {
            sort(emails.begin(), emails.end());
            vector<string> account;
            account.push_back(emailToName[emails[0]]);
            account.insert(account.end(), emails.begin(), emails.end());
            res.push_back(account);
        }
        return res;
    }
};
```
