# 453. 最小操作次数使数组元素相等

## 0. 一句话题意

每次操作把 **n−1 个**元素各加 1，求让所有元素相等的最少操作次数。

## 1. 做题前 30 秒的第一反应

（当时未留记录。以下是回看代码时的复盘，**不是当时的想法**。）

- 直觉：每次都加 n−1 个，等价于"把没被选中的那个减 1"？
- 复杂度预算：n ≤ 10⁵，只能 O(n) 或 O(n log n)
- 想抓的工具：数学/不变量

## 2. 卡点与尝试轨迹

| 版本 | 做法 | 结果 | 为什么行 |
| --- | --- | --- | --- |
| v1 `v1-和减最小值.cpp` | 求 `sum` 和 `min`，返回 `sum - n * min` | 能过 | 反向操作后，每个元素都要减到最小值 |

## 3. 关键洞察（题眼）

**"n−1 个元素 +1" 在相对差值上等价于 "1 个元素 −1"。**

因为所有元素同时加同一个数不改变它们之间的差；而每次操作恰好让"没被加的那个元素"相对其他元素少 1。
于是问题变成：每次选一个元素减 1，最少几次让所有元素相等？

只能减不能加，目标值不能高于当前最小值，所以最优目标是 **最小值 `min`**。
每个元素 `a[i]` 需要减 `a[i] - min` 次，总数 = `sum(a) - n * min`。

## 4. 正确性与复杂度

- 下界：总和每次恰好减少 1（反向视角），最终总和是 `n * target`，`target ≤ min`，所以至少需要 `sum - n*min` 次。
- 可达：对每个元素独立地减到 `min`，总次数正好是 `sum - n*min`。
- 时间 O(n)，空间 O(1)。
- 边界清单：n = 1（返回 0）／全部相等（0）／有负数（公式仍然成立，但注意 `sum` 用 `long long`）／`sum` 最大约 10⁵ × 10⁹ = 10¹⁴，**必须 long long**。
- 题目保证答案在 32 位内，但中间的和不在——这是本题最容易踩的溢出点。

## 6. 可迁移

- 触发信号："每次对 n−1 个元素做操作" → 先试试反过来看"对 1 个元素做相反操作"
- 关键手法：**不变量 / 相对量**——同时加同一个数不改变差值
- 与 [462](../0462-最小操作次数使数组元素相等II/0462.md) 的对比：
  - 453：n−1 个 +1 → 等价于 1 个 −1 → 目标是**最小值**
  - 462：任意一个 +1/−1 → 目标是**中位数**
  - 两题名字几乎一样，操作完全不同，别混
- 下次见到"每次操作影响 n−1 个/除一个以外的所有元素"先想：能不能转成"只影响一个元素"？
