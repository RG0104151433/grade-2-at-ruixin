# 3882. 网格图中最小异或路径

## 0. 一句话题意

从网格左上角走到右下角，只能向右/向下；路径代价是经过格子的**异或和**，求所有路径中的最小异或值。

## 1. 做题前 30 秒的第一反应

（当时未留记录。以下是回看代码时的复盘，**不是当时的想法**。）

- 直觉：路径数量是指数级，不能枚举；但异或值域很小（`grid[i][j] ≤ 1023`），可以记录"每个格子能到达哪些异或值"
- 复杂度预算：`m * n ≤ 1000`，值域 1024，状态数约 10⁶，可行
- 想抓的工具：DP + 可达值集合

| v1 `v1-按步长DP.cpp` | `record[i][j][v]` 表示走到 (i,j) 能否得到异或值 v；按 `i+j` 从左上往右下推 | 能过 | 异或值域只有 1024；转移只依赖上、左 |

## 3. 关键洞察（题眼）

**不要存"最小异或值"，要存"这个格子能到达的所有异或值"。**

因为异或没有单调性：当前异或值小，不代表继续异或后面的数还能得到更小结果。
但题目给了 `grid[i][j] ≤ 1023`，异或结果始终在 `[0, 1023]`，所以可以把"值"直接做成状态的一维。

转移：

```text
reach[i][j][v ^ grid[i][j]] |= reach[i-1][j][v] 或 reach[i][j-1][v]
```

最后在 `reach[m-1][n-1][0..1023]` 里找第一个为真的 v。

代码用 `s = i + j` 按反对角线推进，只是为了保证上、左已经算过；普通的两层 `for i, for j` 也可以。

## 4. 正确性与复杂度

- 为什么对：对步数 `s` 归纳。起点只有一种异或值；每个格子只能从上或从左到达，把所有前驱的可达值分别异或当前格子，就得到当前格子的全部可达值。最终集合包含且只包含所有路径的异或值，取最小即可。
- 时间 O(mn · 1024)：每个状态常数转移。
- 空间 O(mn · 1024)：`1000 × 1024` 个 `int` 约 4 MB，可以接受；也可以滚动成一维。
- 边界清单：单格（答案就是 `grid[0][0]`）／单行／单列（只有一条路径）／异或结果为 0（答案可以是 0，`ans` 初值不要设成 0 后忘了更新）／多条路径得到同一个异或值（布尔状态天然去重）。
- 代码里 `ans = -1` 只是占位；题目保证至少有一条路径，所以最后一定会被覆盖。

## 6. 可迁移

- 触发信号：路径问题 + 运算是异或/集合 + **值域很小**
- 关键手法：把"值"做成 DP 的一维（可达性 DP / bitset 优化）
- 与普通网格 DP 的区别：普通 DP 存"最优值"；这里因为异或不可比大小，必须存"所有可能值"
- 优化方向：`bitset<1024>` 或 `uint64_t[16]` 可以省空间/加速；滚动数组只需保留上一行
- 下次见到"异或路径 / 子序列异或 / 值域 ≤ 2^k"先问：能不能枚举值域做可达性 DP？
