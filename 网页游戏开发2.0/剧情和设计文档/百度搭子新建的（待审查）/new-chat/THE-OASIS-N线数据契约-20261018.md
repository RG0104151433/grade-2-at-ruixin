# 第一部分 · 契约范围与硬约束

## 1.1 本契约覆盖内容

- N 线：N1 对话（合同①出现后扩写，动机自我介绍）→ N2 线索（年鉴馆私人档案格查证 Soron）→ N3 选择 C2（点破 / 周旋 / 共情）→ N4 演出（签约厅终局前，三档手写批注差分）。
- 节点 id、节点类型、触发条件、写在节点上的 flag/clue、批内/批间互锁、差异化回看解锁。
- **合同语义铁律**：签任何合同仍锁死其余结局（buyoutBinding 语义保持）；本线只补动机文本，**零新增放行**。
- ★M→N 联动留口：N3 建议文本（morrow_pressed 差分，非强制实施）。

## 1.2 硬约束（不可违反）

1. **命名以剧本 20261005 为准**：N 线 flag/clue 使用剧本正文定稿命名（`nolan_arc_unlocked`、`nolan_confronted`、`nolan_circumspect`、`nolan_sympathized`）；文档地图 G2 提示 `fynne_`（count=0）为工程检索锚点、`nolan` 命中是剧情文本无关词，均不构成落码依据。
2. **事件类型白名单**：`dialog / setFlag / discoverClue / ifClue(then/else) / ifFlag(then/else) / finaleChoice / changeMap / preload / goalHint / archiveTransition / inviteVerify / indexBook / fade / choice`。
3. **filter 只收 flag，clue 判定必须走 ifClue**：N2 线索「诺兰的旧身份 Soron」为 clue，不得写入任何 trigger 的 `filter/entryFilter`，只能用 `ifClue` 判定防重播。
4. **不触碰四协议解锁布尔**：本契约全部新增状态只是演出、对白、批注差分与结局回顾的素材，**不得写入** inherit / public_energy / charter 的 requirements 或任何协议解锁判定（9.1 声明）；`buyoutBinding` 语义零改动。
5. **资源预算**：0 新图 / 4 节点 / 演出 1 段（N4）；N2 私人档案格按年鉴馆内嵌子场景（0.5 图折算口径申报，9.5 口径）；N3/N4 签约厅场景复用 index_gate 签约厅既有资源。
6. **合同选择沿用既有**：N1 接受/拒绝两选项与文案、二次确认流程沿用 index_gate 既有实现（`deal_nolan_accept1` / `deal_nolan_reject1`），不新增选择 flag。
7. **校验**：按文档地图 G5 三层替代校验规范。
