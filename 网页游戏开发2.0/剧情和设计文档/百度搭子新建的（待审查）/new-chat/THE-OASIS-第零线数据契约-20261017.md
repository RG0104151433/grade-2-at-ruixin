# 第一部分 · 契约范围与硬约束

## 1.1 本契约覆盖内容

- 两段入口：`library` 调查点「落灰服务器柜」（获 `zero_backup_tape`）＋ `finale_transition` 第二选择项「下行：离线湾」（持带后出现）。
- Z 线节点：Z1 演出 → Z2 对话 → Z3 选择（公开/封存/追问，三选一互斥）→ Z4 演出 2（差分收束 + 第六信物）。
- 节点 id、节点类型、触发条件、写在节点上的 flag/clue、批内/批间互锁、reviews 条件引用、双隐藏结局合题与排除项。
- 待决策相关落点：第 3 项（零错过窗口存档策略）与第 4 项（`zero_db_*` 三 flag 互斥写档）裁定的契约化；第 2 项（新图申报口径）已定案为独立关卡单列（见 8.2）。

## 1.2 硬约束（不可违反，沿用 KM-CONTRACT 第一/八部分）

1. **命名以剧本 20261005 为准**：Z 线全部 flag/clue 使用正文定稿命名（见第三/第四部分），不新增备选名、不修改既有 id。
2. **事件类型白名单**：新增节点只允许使用 story_config.js 既有事件类型——`dialog / setFlag / discoverClue / ifClue(then/else) / ifFlag(then/else) / finaleChoice / changeMap / preload / goalHint / archiveTransition / inviteVerify / indexBook / fade / choice`。
3. **filter 只收 flag，clue 判定必须走 ifClue**：`zero_backup_tape`、`witness_release` 均为 clue，不得写入任何 trigger 的 `filter/entryFilter`，只能用 `ifClue` 分支判定；`zero_db_public/sealed/questioned`、`zero_arc_complete`、`sixth_signal_ready` 等为 flag，可进 filter 去重。
4. **不触碰四协议解锁布尔**：本契约全部新增状态仅是演出、对白与结局回顾（reviews）的素材，**不得写入** inherit / public_energy / charter 的 requirements 或任何协议解锁判定；`allAlmanac` / `art3misOnline` 等派生状态零改动。
5. **资源预算（第 5 批）**：新图 1 张（第零章，线框/文本风格残次世界）＋服务器柜子场景（library 内嵌，0.5 图）＋演出 2 段（Z1、Z4）＋结局正文 1 段＋ reviews 增量；详见第六部分。
6. **校验（G5 三层替代校验）**：工程内不存在 verify-config 脚本实体（文档地图 4.5 已定案），落码后按三层替代校验规范执行（静态一致性 → index.html 加载守卫核对 → 动态冒烟），否则视为契约未落地；若项目方日后提供真实工具则优先用工具。
7. **第零线特有**：Z3 三 flag 互斥写档遵循「同帧原子提交，先写者胜出」；倒计时耗尽自动登出回 `finale_transition`，回程**不写任何失败状态**（KM 契约第八部分第 3 项裁定）；双隐藏结局合题与排除项见 4.4。

## 4.2 批内互锁

- Z1 → Z2 → Z3 → Z4 顺序单链，无分支旁路。
- Z3 三选项互斥（先写者胜出）；Z4 差分段仅命中一支；公共前导/收束段三支共用。
- Z 线对 X/K/M 线为**单向只读**：Z4 差分段只读 `zero_db_*`；Z 线不外写任何 X/K/M 状态；不触碰 `witness_token`（M 线第五信物 25 美分硬币）——第六信物与第五信物仅在对偶隐喻与 reviews 层呼应（一放一存），状态层完全解耦。

## 4.3 防重播策略

| 场景 | 行为 |
| --- | --- |
| `zero_arc_complete` 未置位 | finale_transition 下行项可用；进入后完整播放 Z1-Z4 |
| `zero_arc_complete` 已置位 | 下行项保留但不重播完整流程；复看入口＝终局裁决台第六信物槽（若 `sixth_signal_ready`）＋结局 reviews / 结局正文 |
| 错过（未持带过 finale_transition） | 无任何记录（不写 flag、不写计数、无 UI 提示）；此后未能再持有磁带则无下文 |

## 4.4 双隐藏结局与终局裁决台

- **合题**：第六隐藏结局入口条件 `allOf: ['fifth_signature_done', 'witness_release']`——第五信物轨（既有第五结局完成）＋第六信物（`witness_release`）双持。
- **排除项**：主流程走向 `buyoutBinding` 或 `ally_maze_leave` 时，写 **`sixth_arc_sealed`（flag，新增）＝ true**，第六隐藏结局不可达（防错配；与既有 `fifth_arc_sealed` 永久封条逻辑同族，不同时置位/共用）。
- **终局裁决台**：新增第六信物槽「停机日的钥匙」——默认不可见；仅 `sixth_signal_ready` 置位后出现（槽内展示 `witness_release` 实体）。
- **结局记录**：第六隐藏结局观看写 `sixth_ending_seen`（flag，防重播/记录）；结局完成收束写 `sixth_ending_done`（clue，供 reviews 与再入判定）。
